# 待标注工作表

这里的文件**不是黄金集**，评测不会读它们。它们是 `ahr golden-candidates`
从真实提问里挖出来的候选，等人填完才会搬进 `data/golden/`。

## 怎么填

每题三步：

1. **`answerable`** —— 语料里是否真的答得出来。答不出改成 `false`，
   并补上 `presupposition`（这题预设了什么）和 `must_not_claim`（不许出现的词）。
2. **每个文档的 `grade: ?`** —— 改成 `2`（强相关）或 `1`（弱相关）；
   不相关的整行删掉。全删光说明这题应该是 `answerable: false`。
3. **`notes`** —— 写这题考的是什么。将来的人靠它判断题目还成不成立。

最后把 `id` 从 `TODO-xxxxxxxx` 改成 `RAG-GOLD-NNN`（接着现有编号往下排）。

## 填完之前不要合并

```bash
docker compose exec ai-service python -m ahr.cli golden-validate <文件>
```

留着 `?`、`TODO` id 或没写 notes，都会以退出码 1 失败。

## 文档列表从哪来

来自 `rag_trace`——**包含检索看过但丢弃的**。只列被引用的文档，标注者就只能
给系统点头；漏标的相关文档恰恰藏在「未进证据」那几行里。

2026-08-06 之前的提问没有 trace，那些题只能列出被引用的文档，工作表里会
逐题标出来。

就不可比了。新题应当作为独立的「新鲜集」分开跑、分开报告。
