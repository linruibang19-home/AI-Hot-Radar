## 当前状态

`worksheet-20260830.yaml` —— 挖出 30 题，留下 19 题，剔掉 11 题。
**grade 是模型标的（`annotation.method: model_assisted`），还没有人工复核。**

复核之前，用它跑出来的任何数字都必须标注来源，不能和 90 题黄金集的历史

## 怎么填

每题四步：

0. **`category`** —— 六类之一。`data/golden/` 按类分文件，拆分要靠它。
1. **`answerable`** —— 语料里是否真的答得出来。答不出改成 `false`，
   并补上 `presupposition`（这题预设了什么）。`must_not_claim` 可选：
   写错了比不写更糟，它会误伤那些正确点破前提的回答。
2. **每个文档的 `grade: ?`** —— 改成 `2`（强相关）或 `1`（弱相关）；
   不相关的整行删掉。全删光说明这题应该是 `answerable: false`。
3. **`notes`** —— 写这题考的是什么。将来的人靠它判断题目还成不成立。

最后把 `id` 从 `TODO-xxxxxxxx` 改成 `RAG-GOLD-NNN`（现有到 090，新题从 091 起）。

## 填完之前不要合并

```bash
docker compose exec ai-service python -m ahr.cli golden-validate data/golden/pending/worksheet-20260830.yaml
```

留着 `?`、`TODO` id、没写 notes 或 category 不合法，都会以退出码 1 失败。

## 三个把关点

**文档列表来自 `rag_trace`，包含检索看过但丢弃的。** 只列被引用的文档，标注者
就只能给系统点头；漏标的相关文档恰恰藏在「未进证据」那几行里。
2026-08-06 之前的提问没有 trace，那些题只能列出被引用的文档，工作表里会逐题标出来。

**标着「快照外」的文档没有 `id` 行，标不了。** 评测按 `asked_at` 裁快照，
发布时间晚于提问时间的文档取不到——标成相关就是记一笔永远追不回的漏召。
这类文档是真实存在的：信源会在首次抓取之后把 `published_at` 往后改
（真实流量里 4823 条 trace 中有 109 条），今天看到的日期不是提问当时的日期。

**评测回放不算真实流量。** 每跑一次评测，90 道题都会走一遍同样的流水线、
写进同一张 `rag_query` 表——247 行里有 71 行是这么来的。不排掉，挖矿就是
把黄金集读回给它自己：第一批 30 个候选里有 6 个已经是黄金集里的题，其中两道
还是拒答题，它们「支持度低」恰恰是因为系统拒答对了。`golden-candidates`
现在会读 `--golden` 把这些排除掉，并在输出里报 `golden_replays_skipped`。
