# ADR-0036：数值审计无需修改时只回 `ok`，不再全文复述

- 状态：已接受
- 日期：2026-09-24
- 修订：ADR-0023 审计轮的输出契约（新增 `{"verdict": "ok"}`）；ADR-0034 的不变量与 fail-closed 规则不变
- 相关：ADR-0023、ADR-0034

## 背景

答案含两个以上数字且有比较措辞时，ADR-0023 追加一次审计调用。旧提示词要求「若候选答案正确，
原样保留」——即把整份答案重写一遍。本地两次实测（2026-09-24，0922 生产副本）中，审计占一次回答的
2.3 s / 7.2 s 与 2.8 s / 7.5 s；冻结基线里 33 次审计只有 13 次改动了答案，其余 20 次付了一次
完整重写，得到的是原文。

## 决策

1. 审计提示词改为二选一：数字关系全部正确时只输出 `{"verdict": "ok"}`；只要有一处需要修改，
   输出完整的修正后 JSON（原契约）。
2. `ok` 代表**草稿本身**，并与改写稿接受完全相同的检查：ADR-0034 的算术不变量不通过，就进入
   原有的一次修复；修复仍失败则 fail-closed。`ok` 省的是输出，不是校验。
3. 只有恰好 `{"verdict": "ok"}`（不带 `answer_markdown`）才算判定；其他形状仍按完整改写的严格
   schema 解析。
4. 记录 `numeric_audit.verdict`（`ok` / `rewritten`）；生成评测汇总 `verdicts` 与 `ms_mean`。

## 证据（2026-09-24，本地 08-30 语料副本，按提问时间冻结）

逐条数据：`data/eval-runs/audit-ab-golden-20260924.json`、`data/eval-runs/audit-ab-specialist-20260924.json`
（每次审计的草稿、新旧两份原始输出、耗时与 token）。

**配对设计**：新代码真实回答；每次审计把同一份审计输入（同一草稿、同一证据）同时发给旧提示词，
两者顺序逐题交替。比较的是同一草稿上的两个判定，不受生成抖动影响。

黄金集中冻结基线触发过审计的 33 题（本次 31 次触发）：

| | 旧提示词 | 新提示词 |
|---|---:|---:|
| 审计耗时 均值 / p50 / p95 | 3875 / 3530 / 5562 ms | **998 / 687 / 1202 ms** |
| 输出 token 均值 | 1131 | **103** |

| 新判定 \ 旧提示词是否改动（忽略空白） | 改动 | 未改动 |
|---|---:|---:|
| `rewritten` | 2 | 0 |
| `ok` | 9 | 20 |

- 9 次分歧逐条人工核对：旧提示词的改动**全部是拆句**（按其「百分比与货币值分句」指令），
  没有一处改动数字或数字关系；9 份草稿全部通过 ADR-0034 不变量。
- 其中 RAG-GOLD-012 的旧改写把 `[E1]` 挪到下一行行首，下游 `drop_uncited_sentences`
  因此会多删 2 句事实陈述（草稿删 1 句，旧改写删 3 句）。
- 两边都改写的 2 次是 rollout 与每任务两种口径的 P0 形状（RAG-GOLD-007 / 031）。

厂商别名专项集中触发过审计的 7 题（本次 5 次触发，含 P0 RAG-VENDOR-010）：5 次判定**完全一致**
（3 次都改写、2 次都未改）；**RAG-VENDOR-010 新提示词判为 `rewritten`**，没有放过。

本轮 31 + 5 次审计里，旧提示词做出数字关系层面的实质纠正为 0 次。这不等于审计无用：它防的是
低频高危的 P0 形状，冻结草稿里恰好没有出现错误版本。是否整体移除审计仍按 handoff 的判据另行评估。

## 后果

- 触发审计的回答在黄金集上每次约省 2.9 s（均值），输出 token 约少 90%。
- 模型把应改写的草稿判为 `ok` 时，ADR-0034 的不变量仍会拦住「百分比 + 两组货币值」这一类；
  不变量覆盖不到的口径错误（无百分比的每次 / 每任务混用）依赖模型判定，与旧提示词相同。

## 回滚

恢复 `NUMERIC_AUDIT_SYSTEM_PROMPT` 的「原样保留」措辞即可；`parse_numeric_audit_output`
对 `ok` 的接受与 `_audit_candidate` 可以保留，不会被触发。
