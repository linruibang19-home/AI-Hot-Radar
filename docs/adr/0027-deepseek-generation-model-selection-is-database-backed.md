# ADR-0027：DeepSeek 生成模型选择由 PostgreSQL 持有

- 状态：接受
- 日期：2026-08-11
- 关联：AHR-SPEC-000 §8、AHR-API-500 §5、AHR-QSO-700 §3/§5、ADR-0005、TASK-M5-007

## 背景

当前 `LLM_MODEL` 同时控制内容结构化、推荐理由、报告摘要和 RAG 回答。它只存在于部署
环境变量中，页面无法看见，切换需要改生产配置并重启，而且历史 `llm_usage` 只有模型名，
不能证明调用发生时采用了哪一版配置或哪一份价目。

用户需要在不暴露供应商密钥、不改动向量索引的前提下，比较 DeepSeek 生成模型。硅基流动
的 embedding 与 reranker 已经形成 1024 维索引和检索基线，不属于这次切换范围。

## 决策

1. PostgreSQL 新增 DeepSeek 生成模型目录和单例当前配置。目录仅允许经代码与迁移审核的
   模型；首批为 `deepseek-v4-flash` 与 `deepseek-v4-pro`。
2. 一个当前配置统一作用于之后发生的内容结构化、推荐理由、报告摘要和 RAG 生成。切换不
   重写历史内容、不重建 embedding、不刷新缓存中的旧回答；新请求和新批次读取新版本。
3. Core API 提供受 VIEWER 保护的读取接口，以及受 OPERATOR、目标确认、持久化幂等和
   `admin_audit` 保护的切换接口。供应商 API key 仍只在 AI Service 环境中，数据库与 Web
   都不保存它。
4. AI Service 每次创建生成客户端时从 PostgreSQL 读取模型与配置版本；数据库不可用、目录
   行被禁用或配置缺失时快速失败。`LLM_MODEL` 只作为没有 `DATABASE_URL` 的离线测试/工具
   兼容值，不是生产事实源。
5. DeepSeek V4 调用显式关闭 thinking，以保持现有 JSON schema、延迟预算和温度语义。
   thinking 模式需要独立质量/成本回归后另立任务，不能随着模型名切换暗中开启。
6. 每条 `llm_usage` 快照配置版本与当时的三类 CNY/M token 费率。价目含生效日和官方来源，
   页面必须标明它是配置快照而不是账单。

## 后果

- 生成模型可以在页面安全切换，且无需重启服务；最长只影响已经创建但尚未结束的那个客户端。
- 所有生成工作共用一个模型，比较口径清楚，但暂不支持“RAG 用 Pro、日报用 Flash”的分流。
- embedding/reranker、分块、向量维度和 RAG 检索策略完全不变。
- 模型目录与价目会过期；新增模型或更新价格必须通过迁移/审核，而不是允许浏览器输入任意模型名。

## 否决方案

- **把模型名继续放在 `.env`**：无法审计、无法无重启切换，也无法给 UI 读取。
- **让浏览器直接调用 DeepSeek**：会暴露 API key，并绕过成本、审计和输出校验。
- **允许任意模型字符串**：一次拼写错误就会让所有生成任务失败，也无法声明能力兼容。
- **同时开放 embedding 切换**：会造成向量维度/模型混用和全库回填，本任务没有对应迁移门禁。
