# ADR-0035：引用锚点改挂到父块内真正支持论断的分块

- 状态：已接受；第 1、2 条由 [ADR-0037](0037-support-is-judged-per-sentence-for-anchors-not-deletion.md) 修订（按引用它的每一句选，而不是只看 `claim_text`）
- 日期：2026-09-24
- 修订：ADR-0016「生成读父块、引用仍指向命中分块」中**引用指向**的一半；父块扩展本身不变
- 相关：ADR-0016、ADR-0023（支持度门控）

## 背景

ADR-0016 把检索单元和阅读单元分开：小分块用来**找**，父块用来**读**，引用仍指向命中的小分块——
「读者核对一段，模型读够整篇」。

两半在模型从兄弟分块里取事实时互相矛盾。生产实例：回答写「Opus 5.5 API 价格打 8 折」，
引用 [5] 指向量子位文章的 chunk 1（检索命中）；价格在 chunk 0（标题段），chunk 1 里没有任何价格。
支持度门控按整篇父块打分（0.97）放行，读者悬停引用时看到的却是一段不含这句话的文字。

生成评测其实一直在量这件事：段落级支持度（`support_supported`）低于按模型实际读到的父块算的
支持度（`support_as_read_supported`），差值就是这类引用。

## 决策

1. 支持度门控之后、摘录加载之前，对每条存活引用：若其父块处于 `document` 或 `section` 层级，
   用交叉编码器把论断与父块内**模型可见**的各分块逐一打分（一次 rerank 请求，论断对兄弟分块）。
2. **只在命中分块自身不达标（< 0.30）且某个兄弟分块得分更高时才移动**。命中已经支持论断就不动，
   即使兄弟分块略高——两段都支持时换来换去只是读者看不懂的抖动。
3. 只在 `document` / `section` 层级移动：这两层里展开任一兄弟分块都得到同一个父块，
   移动只改变读者看到的段落，不改变模型读到的内容和门控判定的依据。`neighbours` 层每个分块有
   自己的窗口，移动会悄悄换掉评测的 as-read 口径，所以不动。
4. 只考虑模型实际看到的分块：父块在 `MAX_PARENT_CHARS` 处截断，截断点之后的分块不作候选，
   跨截断点的分块按可见部分打分。
5. 与支持度打分并发执行（同一次往返），失败时保留原锚点——提供方故障只能让锚点不变好，
   不能让它乱动。
6. `rag_citation.content_chunk_id` 与返回的 `chunkId` 存移动后的锚点，永久链接与缓存回放因此
   显示同一段摘录；执行轨迹仍按**检索命中**标记「已引用」，因为轨迹解释的是检索。
   `metrics.anchors_moved` 记录每次回答移动了几条。

## 证据（2026-09-24，本地 08-30 语料副本，按提问时间冻结）

对冻结基线 `m4-rag-eval-GEN-FROZEN-20260924.json` 的全部 278 条引用离线重放：论断不变，
只换锚点，交叉编码器 `BAAI/bge-reranker-v2-m3` 按段落打分（逐条引用统计，非逐题平均）。

| | 重选前 | 重选后 |
|---|---:|---:|
| 段落级支持度均值 | 0.8527 | **0.9016** |
| 段落级达标率（≥ 0.30） | 0.9173 | **0.9748** |
| 不达标引用数 | 23 | **7** |

- 层级分布：`document` 166、`neighbours` 108、`section` 4；有可见兄弟分块的 65 条；实际移动 19 条。
- 剩余 7 条不达标：1 条移动了但仍不达标（0.117 → 0.259）；6 条未移动——没有可见兄弟分块，
  或兄弟分块都不比命中更好。
- 典型移动：llama.cpp 发布说明里，论断「默认端口将从 8080 改为 9931」原指向二进制下载列表分块，
  现指向 `server: add notice for upcoming default port change 8080 --> 9931` 所在分块。

离线重放而不是重新生成，是为了配对比较：生成本身在 ±0.02 内抖动，与预期效果同量级，
重跑 90 题比不出来。

## 后果

- 每条有兄弟分块的引用多一次 rerank 请求（SiliconFlow），与支持度打分并发，不增加串行往返。
- 摘录仍是锚点分块的前 260 字。论断落在长分块后半段时，摘录依然可能不含那句话；
  这是摘录窗口的问题，需要单独处理（按论断选窗口会让永久链接与实时回答的摘录不一致，需另行设计）。
- 评测的 `support_supported` 从此量的是移动后的锚点；与 2026-09-24 之前的数字比较时要注明。

## 回滚

删除 `service.answer_question` 中应用 `anchors` 的几行即可；`rag.anchor` 与
`ParentBlock.chunk_texts` 留着不影响任何行为。
