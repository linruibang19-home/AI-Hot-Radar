# ADR-0026：报告订阅与邮件投递事实归 Core API

- 状态：已接受
- 日期：2026-08-11
- 相关：`AHR-FEAT-105`、`AHR-ARCH-200` §3/§5、`AHR-QSO-700` §3/§5、
  `AHR-RUNBOOK-1100` §6、ADR-0025、`TASK-M5-004`

## 背景

现有 Python `send-report` 命令能够向一个显式收件人发送已保存日报，并用
`email_delivery.delivery_key` 阻止手工重发；它没有订阅者、确认、退订、时区或自动调度。
把这些事实继续放在 AI 服务会违反 `AHR-ARCH-200`：用户与订阅属于 Core API，AI 服务只
负责内容加工和模型能力。

公共订阅入口还必须同时解决三类风险：他人替邮箱地址订阅、服务重启后重复投递，以及邮件
失败反向拖住采集和站内报告发布。

## 决策

### 1. Core API 是订阅和投递的唯一事实所有者

PostgreSQL 保存 `report_subscription`、周期偏好、待确认请求和投递状态。Core API 提供公共
订阅、确认、退订 API，并负责 SMTP 投递；Web 只提供同源代理和交互。Python 中现有
`send-report --dry-run` 继续作为运维预览工具，不再承担用户订阅调度。

### 2. 采用双重确认，公共响应不泄露邮箱是否已存在

每次提交都创建或刷新一条待确认请求，daily/weekly/monthly 偏好和 IANA 时区先保存在请求
中。只有收件人点击 24 小时内有效的确认链接，偏好才原子写入 ACTIVE 订阅。重复提交统一
返回 202，不能用响应枚举已订阅邮箱。

确认和退订令牌由目标 ID、动作、版本和过期时间组成，并使用服务器专用
`AHR_SUBSCRIPTION_TOKEN_SECRET` 做 HMAC-SHA256 签名。数据库不保存可直接使用的令牌；
退订会增加 `token_version`，使旧链接失效。令牌和邮箱不得进入日志、审计详情或 URL 查询到
Core API；浏览器只把令牌通过同源 POST 代理提交。

### 3. 只投递 PUBLISHED，并以数据库唯一键保证至多一次

调度器每五分钟检查 ACTIVE 订阅。每个周期只选择确认时间之后最新的 PUBLISHED 报告，且
等待用户当地时间达到 08:30。`(subscription_id, report_id)` 是唯一投递事实；同一期同一
收件人即使多实例并发、进程重启或请求重试，也只能创建一条记录。

待投递记录使用 `FOR UPDATE SKIP LOCKED` 原子领取。领取 15 分钟后仍为 SENDING 的记录会
按已计尝试次数恢复为 RETRYABLE_FAILED 或 PERMANENT_FAILED，避免进程崩溃留下永久卡单。
SMTP 最多尝试三次，退避为 10 分钟、60 分钟，第三次失败进入 `PERMANENT_FAILED`。正式
邮件包含对应报告的原文链接和一键退订入口，不在投递时重新调用 LLM。

数据库能保证同一订阅与报告只有一条投递事实，但普通 SMTP 不提供幂等键：若服务器已接收
邮件而进程在写 SENT 前崩溃，恢复后存在极低概率重复发送。这里选择“可恢复且可能重复”而非
“标记成功后发送并可能永久漏信”；要获得端到端 exactly-once，必须改用支持幂等键的邮件 API，
届时需另立 ADR。

### 4. 邮件失败是非阻塞输出失败

SMTP 未配置、超时、退信或订阅为空都不得改变报告状态，也不得阻塞采集、精选、Story、
RAG 或站内报告。失败状态保存在 PostgreSQL，允许运维 dry-run 和后续人工重试。生产预检
必须要求 SMTP 发件地址和签名密钥；本地验收使用 Mailpit，不联系真实邮箱。

## 备选方案

- **把订阅放在 AI 服务**：复用现有 Python 邮件代码较快，但违反已锁定服务边界，拒绝。
- **点击一次立即订阅**：实现最少，但任何人都可替他人订阅，拒绝。
- **引入 RabbitMQ/外部邮件队列**：当前单机规模没有数据证明需要；PostgreSQL
  `SKIP LOCKED` 已满足幂等与并发，暂不引入。
- **为每位订阅者重新生成报告**：成本高且会造成 Web 与 Email 事实漂移，拒绝。

## 后果与回滚

- 新增四张小表并扩展现有 `email_delivery`，由 Flyway V023 管理；
- Core API 增加 Spring Mail 依赖和一个轻量定时任务；
- 邮箱为完成投递所需的业务数据，以规范化形式保存，但所有日志必须脱敏；
- 若自动投递需要停用，可关闭调度配置，站内报告与手工 dry-run 不受影响；
- 回滚应用版本时保留新表和记录，不执行破坏性逆向迁移。
