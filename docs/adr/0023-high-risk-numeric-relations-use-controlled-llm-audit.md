# ADR-0023：高风险数值关系增加一次受控 LLM 审计

- 状态：已接受
- 日期：2026-08-11
- 相关：`AHR-RAG-400` §9–§10、`AHR-QSO-700` §8、ADR-0021

## 背景

中文厂商专项集的成本题同时给出两种口径：`$4.65/$8.37 per rollout`，以及
`64% less per completed task`。生成模型两次把 64% 错挂到单次运行价格上；
交叉编码支持度仍接近 1，因为被引段落同时包含全部数字。提示词 v5/v6 可以降低
发生率，却不能消除同一提示在不同生成轮次中的随机复发。

这说明 ADR-0021 的交叉编码器适合判断主题和段落支撑，却无法可靠验证数字之间的
单位、分母和因果关系。该错误会带着真实引用通过现有门禁，属于最危险的 P0 形态。

## 决策

当答案同时包含多个数字，并出现百分比、倍数或高低/成本比较关系时，生成后增加
**最多一次**受控 LLM 审计：

1. 审计器只读取原问题、候选答案和已经提供给生成器的原始证据；
2. 审计器必须保留数字的单位、分母与比较口径，可修正或删除错误关系；
3. 审计结果仍是不可信输出，必须重新经过 JSON 解析、服务端引用绑定、支持度门禁和
   invariant 校验；
4. 审计调用遵循现有 LLM 客户端的超时、重试、token 用量和可观测性约束；
5. 首次审计若结构无效或仍违反数值安全 invariant，允许**一次**携带明确错误原因的
   结构修复；第二次仍失败、或审计服务不可用时，按 fail-closed 拒答，不发布草稿；
6. SSE 仍可展示首轮草稿，但最终 `answer` 事件必须用审计后的验证答案替换它。

该审计不是所有回答的第二次生成。触发器必须是可复现的本地规则，并在 metrics 中记录
`numeric_audit.triggered/status/attempts/ms`，以便统计额外成本和误拒率。模型调用上限为
首次审计加一次结构修复，不允许继续重试。

## 后果

- 高风险数字问题增加一次模型延迟和费用，普通事实题不变；
- 不能再以交叉编码高分作为数值关系正确的充分条件；
- 流式草稿可能被最终答案修正，前端继续以最终 `answer` 事件为唯一持久化内容；
- 黄金集需保留单位/分母对抗题，并同时报告审计触发率、失败关闭率和人工 P0 结果。

## 不采用的方案

- **继续只改提示词**：定向回放正确、全量回放复发，已被实测否决；
- **只检查数字是否出现在证据中**：本缺陷的所有数字都在同一原文中，存在性检查必然
  放行；
- **用生成摘要作证据**：摘要只能作为检索提示，不能替代原始 passage，也无法证明
  数字关系。
