# ADR-0021：`citation correctness` 判据取蕴含分，不取与黄金集标注的重合度

- 状态：已接受
- 日期：2026-08-09
- 相关：`AHR-QSO-700` §8（citation correctness ≥ 0.90；无「引用存在但不支持结论」的 P0）、`AHR-RAG-400` §10、ADR-0016（父块由查询派生）、ADR-0020（abstention 判据）

## 背景

`AHR-QSO-700` §8 要求 `citation correctness ≥ 0.90`，同样**没有定义怎么算**。
实现里唯一形状相近的指标是 `citation_precision`：
**被引文档落在黄金集 `relevant_items` 里的比例**。它的读数一直在 0.58 上下：

| 轮次 | `citation_precision` |
|---|---:|
| 20260804 | 0.5883 |
| 20260807-fixed | 0.5782 |
| 20260809-gated | 0.5988 |

按字面读，这条门禁差着 30 多个百分点。**但这个数不能这么读。**

黄金集 90 题共标注 **127 个 item**（均 1.6 篇/题），
而实测**平均每条回答引用 3.6–4.0 篇**。
一篇真正相关、只是标注时没被列进去的文档，在这个指标下**计为引错**。

也就是说 `citation_precision` 是一个**下界**，不是估计，
而它的上界受制于标注密度而不是系统质量。**0.90 在当前标注下可能根本不可达**，
把它当门禁判据，衡量的是标注有多完备，不是引用有多正确。

要让它可达，只有穷举式标注一条路——成本极高，且**语料每小时增长**，
标注会持续腐烂（`--validate` 已实测语料自标注以来增长 63.7%）。

## 决策

**`citation correctness` 的判据改为 `support_supported`：
交叉编码器判定（论断 × 被引段落）达到支持度阈值的引用比例。**

理由是它**与标注完备性无关**——它问的是「这段证据支不支持这句话」，
不需要知道语料里还有哪些文档也相关。这也正是 §10 第 ③ 层要求的那个判断，
以及 `rag_citation.support_score` 这一列当初定义出来要装的东西。

### 打分基准取**被引段落**，不取父块

这一条是本 ADR 的实质内容，容易搞错。同一条引用有两种打分口径：

| 口径 | 打给什么文本 | 回答什么问题 |
|---|---|---|
| **段落级**（本 ADR 采用）| 被引 `content_chunk.body_text` | 读者点开这条引用，能不能就地核对 |
| 父块级 | 模型实际读到的父块展开文本 | 模型的论断是否被它读到的证据蕴含 |

**必须取段落级，因为线上门控用的是父块级。**
门控只放行父块级达标的引用，所以父块级读数**只能反映门控自己放行了什么**——
它是同义反复，不是测量。这与 ADR-0020 记的是同一个陷阱的另一面：
**一旦拿某个数去做门控，那个数就不再是测量。**

段落级是门控**没有**强制的那个量，因此它还能失败，因此它才值得当判据。
两个数在报告里并列输出（`support_*` 与 `support_as_read_*`），
名字不同、口径写明，**任何引用其中一个的地方都必须说明取的是哪个**。

## 后果

- `citation_precision` **保留在报告中**，作为「答案是不是读起来对、引错了」的诊断信号，
  按类别看仍然有用（`explainer` 0.74 vs `recent_updates` 0.52 是有意义的对比），
  但**不再作为门禁判据**。
- 门禁「无引用存在但不支持结论的 P0」与本条判据是同一件事的两种表述，
  合并读作：`support_supported`（段落级）→ 1.0。
- 阈值 `SUPPORT_THRESHOLD = 0.30` **仍未标定**，这是本判据最大的软肋。
  它当前的地位是「线上与离线共用同一个数，所以两边可比」，
  而不是「0.30 是正确的分界」。标定它需要人工核对一批跨越阈值的引用，已列为任务卡。

## 已知局限

**交叉编码器不是 NLI 模型。** `bge-reranker-v2-m3` 训练目标是检索相关性，
用它的分数当蕴含代理是 §10 明确允许的（「NLI/cross-encoder 或受控 LLM」），
但它对**否认句**系统性偏低——3.29 实测同样三段挂在否认句上只有 0.15 / 0.27 / 0.50。
支持度门控上线后 `abstention` 类段落级支持度从 0.6158 升到 0.9670，
说明门控把这些低分引用清掉了，**但清掉不等于那些引用真的错**，
只是这个代理认不出它们。换用受控 LLM 判官可以验证这一点，成本是每条引用一次模型调用，
已列为任务卡而不是假装它不存在。
