# ADR-0034：数值安全不变量改为算术一致性校验

- 状态：已接受
- 日期：2026-09-24
- 修订：ADR-0023 决策第 5 条「数值安全 invariant」的判定口径；ADR-0023 其余条款不变
- 相关：ADR-0021、ADR-0023

## 背景

2026-09-23 生产上「Claude Opus 5.5 的 API 价格降了多少？」被拒答
（`numeric_audit.status = invalid_fail_closed`，总耗时 27.6 s），而证据库里有完整价格表。
在生产容器内以只读方式（`PGOPTIONS=-c default_transaction_read_only=on`）重放两次：

- 生成草稿完全正确；
- 审计首轮保留了「缓存读取价格从每百万 token $0.50 降至 $0.20，下降 60%」这一句；
- 旧 invariant 只要一句里同时出现百分比和两个货币值就判为不安全；修复轮以 temperature 0
  原样返回同一句，于是整份答案 fail-closed。

旧规则针对的 P0（ADR-0023）是「每个任务便宜 64%，即 $4.65 对 $8.37」：64% 是每个完成任务的口径，
两个价格是单次运行的口径。两者的区别在**算术**，不在排版：60% 正是 $0.50 → $0.20 的降幅；
64% 既不是 $4.65 与 $8.37 之间的变化率（44% / 80%），也不是二者之比（56%）。

另一个误读也在这次排查中被纠正：`passed` 只表示审计输出结构合法。审计稿总会替换草稿，
而 metrics 从未记录它是否改动过内容，所以「线上 17 次 passed、从未纠正过答案」这个结论不成立。

## 决策

1. 一个子句（按 `。！？；` 与换行切分）同时含百分比与两个以上货币值时，只有当**每个**百分比都能由
   子句内某一对货币值算出，才视为安全：
   - 子句含变化措辞（降、涨、便宜、贵、高、低等）：只接受变化率 `(高−低)/高` 或 `(高−低)/低`；
   - 不含变化措辞：另外接受比值 `低/高`（「为原价的 80%」）；
   - 容差 1 个百分点，覆盖来源的四舍五入。
2. 分号视为子句边界。模型用「；」把两种口径显式分开，正是审计提示要求的行为；P0 的「，即」
   仍落在同一子句内。
3. ADR-0023 的其余约束不变：最多一次审计加一次结构修复，第二次仍失败则 fail-closed；审计只能改写，
   不能引入新证据。
4. 增加记录：`numeric_audit.changed`（审计稿是否改动了草稿）与 `numeric_audit.failures`
   （`unparseable` / `unsafe_mix`）。生成评测逐题保存 `numeric_audit` 并在摘要中汇总
   触发、改动与 fail-closed 次数。

## 验证

- 单元测试：09-23 被拒的原句通过；ADR-0023 的 P0 句及其带「；」的变体仍被拦；
  「从 $0.50 降至 $0.20，下降 40%」仍被拦（40% 是比值，不能用来解释「下降」）。
- 生产重放捕获的 6 份真实模型输出：旧规则下第二次重放的 3 份全部被拒（即线上拒答的成因），
  新规则下 6 份全部通过。
- 本地回归：见下方「回归结果」。

## 后果

- 「价格降了多少」这类最常见的数字问题，不再因排版规则被整份拒答；
- 算术一致不等于口径一致：若一对价格恰好能算出一个错挂的百分比，规则会放行。1 个百分点的容差
  让这种巧合很少见但不为零，审计提示里「百分比与两组货币值分句」的要求仍作为第二层；
- 货币识别仍只覆盖 `$` / `¥` 前缀，「4 美元」这类写法不参与判断，与旧规则相同；
- 有了 `changed` 之后，`numeric_audit` 的去留可以用线上数据回答，而不是再靠推测。

## 不采用的方案

- **删除 `numeric_audit`**：它针对的 P0 真实发生过，而线上无法证明它从未纠正过答案；
  等 `changed` 数据积累后再议；
- **fail-closed 改为只删违规句**：会改变 ADR-0023 的核心安全语义，这次的缺陷不需要它；
- **提高修复轮 temperature，期望模型拆句**：不可复现，也无法测试。

## 回归结果

本地 2026-09-24，语料为 08-30 的生产副本（3,327 条），模型 `deepseek-v4-flash`：

| 集合 | 审计触发 | 改动了草稿 | fail-closed | 旧规则会拒的最终答案 |
|---|---:|---:|---:|---:|
| 黄金集 90 题（`GEN-NUMAUDIT-20260924`） | 37 | 12 | 0 | 0 |
| 中文厂商专项 15 题（`SPECIALIST-NUMAUDIT-20260924`） | 7 | 3 | 0 | 0 |

- 两个集合里所有审计都在第一次就通过，新规则没有被触发，所以**本次改动在这两个集合上没有造成
  回归**，它的收益只在 09-23 的生产重放中出现；
- ADR-0023 的 P0 题 `RAG-VENDOR-010` 仍把单次运行 $4.65 / $8.37、每个完成任务低 64%、
  2.8 倍三种口径分开陈述；
- 审计在 44 次触发中改动了 15 次（34%），它不是空转。这些改动是否都是纠正，本次没有保存草稿，
  无法判定，下一步应在改动时保存草稿摘要；
- 与 08-30 发布基线相比的其他差异（引用精确率 0.6663 → 0.5673、陷阱题直接拒答率 0.5 → 0.0 等）
  **不能归因于本次改动**：生成评测没有按 `asked_at` 冻结语料，本次语料更大，出现了未来信息泄漏
  （`RAG-GOLD-080` 在 08-03 的提问下引用了 08-12 发布的内容）。陷阱题的「错误前提采信」仍为 0 / 12。
