# 15｜测试策略、关键取舍、剩余风险与演进

## 1. 测试金字塔按风险组织

| 层 | 证明什么 | 代表 |
|---|---|---|
| 纯函数单测 | 分块、时间、融合、token、状态规则 | Python/Java/TS tests |
| Repository/集成 | PostgreSQL、pgvector、锁、约束、Flyway | Testcontainers/CI DB |
| 契约 | Java/Python/Web DTO 一致 | schema/spec checks |
| 构建 | server/client、JDK、镜像依赖 | Next build、Maven、Docker |
| 离线评测 | RAG 检索/生成质量 | 90 题 + 专项集 |
| 生产 smoke | DNS/TLS/health/核心页面 | 受控发布验收 |

第三方真实站点不进入高频 CI；使用 replayable fixture。生产 canary 低频验证真实网络，把“代码
回归”和“外部站点变化”分开。

## 2. 这个项目真正有价值的工程亮点

1. 发现与全文分离，避免 RSS 摘要污染证据；
2. 原始响应、revision、chunk、story、report、answer 分层；
3. PostgreSQL dense/sparse/temporal 混合检索与可解释实验；
4. child 精确引用 + parent 生成上下文；
5. 模型输出解析、编号绑定、支持检查和拒答的硬出口；
6. 90 题黄金集、负结果和发布门；
7. 报告审核、双重确认订阅和投递幂等；
8. 单机 Compose 的安全、备份、不可变镜像和容量治理；
9. 明确承认 Outbox 未消费，不用预留表包装架构。

## 3. 关键技术取舍

### PostgreSQL + pgvector，而不是 ES + 专用向量库

当前规模下过滤、事务、引用关系和向量同库更简单。代价是全文相关性和超大规模扩展有限；以
真实 SLO/数据量作为拆分触发。

### 数据库轮询，而不是消息队列

锁、状态和幂等已满足当前吞吐，少一个基础设施。代价是共享库负载和任务可观测性需要自己做。

### Java + Python，而不是单语言

稳定业务状态与 AI/采集生态分别选择合适工具。代价是契约、部署和故障边界更复杂，需要共同
数据库规则和测试。

### 单机 Compose，而不是 Kubernetes

符合 2C4G 和单人运维。代价是主机级故障需要备份恢复/迁移，不能提供多可用区自动容灾。

## 4. 当前剩余风险

- source 质量会随第三方页面变化，需要 fixture 和 probe 持续维护；
- 自动 citation support 不能代替所有人工事实审计；
- 2C4G 在语料、并发和评测增长后需要容量观测；
- SMTP 缺少供应商端严格幂等时仍有极小重复窗口；
- 管理 Bearer Token 适合单运营者，不是多用户 RBAC；
- Outbox 只写不消费，应持续有界清理和明确语义；
- 当前 embedding 单模型，未来切换需要双索引/回填方案；
- 静态评测快照需要在模型/语料/策略变化后重跑。

## 5. 演进触发，而不是愿望清单

| 候选 | 触发证据 |
|---|---|
| RabbitMQ/Kafka | 持续 backlog、轮询干扰查询、消费者独立扩缩容 |
| OpenSearch | PostgreSQL FTS 无法满足相关性/SLO，且优化已证伪 |
| 专用向量库 | 向量量级/过滤/多租户使 pgvector 不再满足 |
| 对象存储 | raw/附件使数据库备份不可控 |
| Kubernetes | 多节点、滚动发布和资源隔离收益超过运维成本 |
| 用户账号/RBAC | 个性化、团队权限和多运营者成为真实需求 |
| GraphRAG | 多跳问题持续失败且关系检索实验显著提升 |

## 6. 如何学习完整项目

第一周先画四条链路和 ER 图；第二周每条链路选一条请求做代码断点/日志走读；第三周重跑一组
测试和一个负实验；第四周用 30 秒、3 分钟、10 分钟三种长度讲述，并让对方从任一表或失败点
追问。背技术名词不如能说明输入、提交点、失败、恢复和取舍。

## 7. 不能夸大的地方

- 不是微服务/Kubernetes 大规模平台；
- 没有真正 Outbox consumer；
- 页面上的评测不是实时刷新；
- source 数是配置规模，ACTIVE 数是动态状态；
- 自动指标不是事实正确率的全部；
- provider 成本是价目估算，不是账单；
- 当前生产计数是带日期快照，不是永久容量承诺。
