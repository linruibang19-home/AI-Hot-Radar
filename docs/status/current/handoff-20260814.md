## 4. 标准发布流程

1. `codex/<task>` 单任务分支开发并完成相关门禁；
2. push、PR、GitHub CI 全绿后合并 `main`；
3. 为合并提交打 `v*` 标签，Release workflow 发布同 SHA 三镜像；
4. 服务器 `production` 仅 fast-forward，`IMAGE_TAG=sha-<HEAD>`，运行
   `infra/scripts/deploy-production.sh`；
5. 验证 HTTPS、核心页面、管理边界、RAG、备份和容器健康；失败时回退上一不可变 tag。

不要在服务器直接开发，不要上传本地 `.env`。GitHub 是代码事实源；服务器只持有生产密钥、
数据卷、备份和运行镜像选择。
