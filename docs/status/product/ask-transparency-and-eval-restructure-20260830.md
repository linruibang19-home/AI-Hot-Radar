# AI 问答链路呈现与 RAG 质量页重排

日期：2026-08-30
分支：`fix/cut-model-console-and-report-waste`（未推送）

## 起因

两条反馈，指向同一个结构问题：

1. AI 问答页「太丑太冗余，小字太多」
2. RAG 质量页「没什么用，做不到实时更新就不做了」

先量化再动手。结论是：问答页的问题不是样式，是**同一个数字在一屏里出现三到五次**；
质量页的问题不是「不实时」，是**页面在为一个线上根本没在跑的配置背书**。

## 一、AI 问答：一屏之内的重复计数

### 改之前

一次回答渲染 11 个区块。同一个量出现在多处，且数值不一致：

| 量 | 出现次数 | 页面上的三种写法 |
|---|---|---|
| 信源数 | 3 | `5 家信源`（chip）· `4 家发布方`（证据概览）· `4 个信源`（页脚） |
| 证据/引用数 | 5 | `10 段证据` · `4 条引用` · `4 条` · `10 段证据` · `4 条被引用` |
| 候选数 | 2 | `101 条候选`（检索过程）· `40 个候选`（为什么是这几条证据） |

前两个是同一件事换了三个词；第三个是**两个不同阶段共用了「候选」这一个词**——101 是 RRF
融合后的候选总数，40 是进入交叉编码器重排的窗口，两个数都对。

小字类名有 12 种：`ask-plan-range` `ask-step-detail` `ask-source-meta` `ask-source-claim`
`ask-example-shows` `trace-meta` `trace-score` `trace-boost` `ask-refusal-note`
`ask-history-note` `ask-sources-count` `eval-meta`。

根因：每加一个功能就顺手加一行计数器，没人回头看过已有的那些。

### 改之后

**两个折叠面板合成一个漏斗**，每一级都有名字，摘要行常驻不折叠：

```
召回 101 → 重排 40 → 证据 10 → 引用 4        15.0s   全过程 ▾
```

点开分三段：耗时分布 / 关键决策 / 候选去向。候选表默认只显示进入证据集的 10 条，
「展开全部 40 条」是二级。

- chip 从 7 个减到 2 个（问题类型、时间窗），其余搬进折叠面板，各说一次
- 删除「证据概览」整块，四个数字并入「引用来源」标题行
- 页脚只留永久链接，耗时并入漏斗行
- `[n]` 引用标记悬停直接看被引段落原文，不再需要点击跳转后回读
- 支持度从裸浮点数 `支持度 0.42` 改成一个标记，数值移到 tooltip
- 空状态从九段文案（kicker + 导语 + 三条能力 + 标签 + 四个例子各带副标题 + 底部五行说明）
  收到三行

新增文件 `apps/web/src/components/AnswerTrace.tsx`，删除 `RetrievalTrace.tsx`。

### 顺带修掉的两个缺陷

**① 耗时写死四个阶段，导致「其他」是最大的一段。**
前端原本只统计 embed / rerank / generate / support，第一条真实回答上「其他」就占了
15.0s 中的 5488ms——比生成还多。改成从 `metrics.stages_ms` 排序推导后，那 5488ms
里露出了 **`numeric_audit` 数字核对 3601ms**，是整条链路第二贵的阶段，页面上从来没有名字。

| 阶段 | 耗时 | 占比 |
|---|---|---|
| generate | 4255ms | 28% |
| **numeric_audit** | **3601ms** | **24%** |
| support | 2864ms | 19% |
| rerank | 2375ms | 16% |

尚未处理：数字核对占四分之一延迟是否值得，需要单独评估。

**② 永久链接看不到耗时。**
耗时原先由前端从 SSE 进度事件重建，而永久链接页面根本收不到那些事件——专门用来分享的
那一页反而没有耗时可看。改成读 `metrics.stages_ms`（答案落库时就存了），直连与永久链接
走同一条渲染路径。

### 验收

- `npx vitest run`：11 文件 / 106 用例通过
- 新增守卫 `describe("pipeline numbers have exactly one home")`，6 条，钉住
  「哪个数字允许出现在哪里」——这正是退化掉的性质
- 浏览器实测永久链接 `ba1b8d19`（即反馈截图那一条），漏斗四级数值自洽

## 二、RAG 质量页：不是「不实时」，是「不对应线上」

### 先澄清一个前提

**评测做不到实时是对的，不是缺陷。** 题集、语料、判据三者固定，轮次之间才可比；
跟着线上提问实时变的话，今天 recall 高可能只是今天的问题简单。

### 真正的问题

1. 页面快照写的生成模型是 `deepseek-chat`，**线上实际跑的是 `deepseek-v4-flash`**。
   一个为没人在跑的配置背书的门禁，等于没有门禁。
2. 405 行里约 300 行讲 B1–B13 历史演进，只有约 60 行讲「当前能不能发布」。主次颠倒。
3. 门禁的两个指标（误拒率、引用支持度）**只在 90 题黄金集上算过，从没在真实提问上算过**。
   一个只在没人写下来的问法上出现的退化，没有任何东西在盯着。

### 改动

**页面倒过来：** 当前门禁 → 门禁五个数 → 线上实测（新增）→ 三张结论卡 →
`<details>` 算法演进记录（B1–B13 + RAGAS 对照 + 生成侧，一个字没删）。

**新增「线上实测」区**，把门禁的同两个指标换成真实提问重新算一遍，并排放：

| 指标 | 固定评测 · 90 题黄金集 | 线上实测 · 近 30 天 |
|---|---|---|
| 拒答 | 0 / 65 可答题误拒 | 2.9%（7 / 241） |
| 引用支持度达标率 | 96.3% | 91.6%（951 / 1038，中位数 0.9127） |
| 无引用的回答 | — | 2 |
| 语料 | 915 条，冻结于标注当时 | 实时 |

两边**不合并成一个分数**：左边固定、可比，答「改动有没有让质量退步」；右边实时、不可比，
答「固定题集还像不像真实提问」。

**新增快照漂移告警：** 页面比对 `release.snapshot.generationModel` 与近 30 天实际写答案的
模型（来自 `llm_usage.operation = 'rag_answer'`），不一致时在门禁面板里以 alert 样式明说
「这块门禁不能代表线上正在跑的配置」。把一个静默的错误陈述变成一个可见的警告。

**不重复 `/ops`：** 候选去向、通道归因、重排深度这些检索侧线上统计 `/ops` 已经有一整块，
质量页只给链接。刚花一整轮消灭重复计数，不能在另一页再造一份。

### 后端

- `apps/ai-service/src/ahr/rag/ops.py` 新增 `live_quality_summary()`
- 挂在既有 `/rag/stats` 下，键名 `quality`
- `SUPPORT_THRESHOLD` 从 `ahr.rag.support` 导入，不重复定义——页面说「支持」必须
  和评测统计的是同一个阈值
- 新增 `tests/test_ops_live_quality.py`，8 条通过

### 写这个功能时自己踩的坑

第一版统计缓存重放用了 `metrics -> 'cache' ->> 'outcome' IS DISTINCT FROM 'miss'`。
JSON 键缺失时该表达式为真，于是**所有缓存指标出现之前写入的旧记录都被算成了缓存命中**：
报出 130 / 241，实际是 4 / 241。数字看着完全合理，错的方向恰好是让缓存好看。
已修（要求 `IS NOT NULL AND <> 'miss'`）并加了专门的回归用例。

这与既有的「缓存 / 时区 / 指针状态」缺陷模式同族：静默错数据，不报错。

## 三、链路呈现的三处错（两处是同一天我自己写进去的）

### ❶ 是三路检索，面板写死成「双通道」

`dense` 和 `sparse` 之外还有 `temporal`（问题能解析出实体时是 `entity_temporal`），
只要规划器解析出时间窗就会跑。面板从 `metrics.channels` 里只读两个键，第三路完全不显示——
而它旁边的候选表几乎每行都写着 `sparse+entity_temporal`。

真实数字：`稠密 60 · 关键词 40 · 实体+时间 13 → 融合 101`。
此前显示的 `稠密 60 · 关键词 40 → 融合 99` 连加法都对不上，这本该是个信号。

改成渲染整个 map 并数出路数，加第四路时它自己会出现。

### ❷ 漏斗行把三路压成一个「召回」

混合检索是这个项目最核心的设计，压成一个数之后，那行读起来就是「召回直接喂给重排」。
改成通道竖排后汇入融合。

### ❸ 引用悬停弹的是模型的话，不是原文

弹出的是 `claim_text`——模型自己写的那句。在一个专门用来证明「有据可查」的面板里，
把模型的话摆在原文该在的位置，等于请读者拿模型验证模型。

新增 `Citation.excerpt` 取 `content_chunk.body_text` 原文，直连与永久链接共用同一个长度
常量（`_CONVERSATION_SELECT` 改成 f-string，不留第二处字面量）。原文在上、模型的话在下
标「本文据此写道」。

### 同屏的其他可用性问题

- 「引用来源」和「全过程」是裸 `<summary>`，没有 hover、没有按钮质感，默认三角还被隐藏了
- 引用只能从答案跳到来源，回不来（来源里的 `[n]` 现在是按钮，跳回首次用到它的那句）
- 模型与 prompt 版本一直在 `metrics` 里，从没显示过
- 「检索用的问题」改成常驻，没改写时明写「原样检索」

## 四、门禁：拒答终于说得出原因

`refused` 是一个布尔值，底下压着三种互不相干的机制：模型自己不答、支持度门删光引用、
`drop_uncited_sentences` 删光句子。三者输出同一句话，所以一份跑完的报告里
`over_refusal_rate` 动了 2.56pt，而报告本身不含任何能解释它的信息。

加上 `refusal_cause` 后重跑 90 题：

```
over_refusal_rate    = 0.0256
over_refusal_causes  = {'all_sentences_uncited': 2}
over_refused_questions = ['RAG-GOLD-034', 'RAG-GOLD-044']   # 都是 comparison
```

**并列的另一个假设被直接排除**：`3de11d0` 改重排维度后同信源限流把 dev 版本挤出证据集——
不是。一次查表代替一次 git 考古。

判断顺序本身有个遮蔽 bug，一并修了：支持度门在删句之前跑，删光引用会**机械地**让所有句子
变成无引用，所以先查后面那一级会把上游原因盖住。改成上游优先，并记下被删掉的句子本身
（最多三条）——否则「为什么被拒」可查而「那句为什么没引用」仍然不可查。

## 五、会话记住自己宣布的时间窗

第一轮解析出 08-22 至 08-29 并显示在页面上；第三轮「那安全漏洞呢」把主语带过来了，
时间没带，于是全语料检索，而上面那行仍然写着一周。**读者看到的范围和拿到的结果是两回事。**

时间窗现在跟着 transcript 走，和旁边的引用标题同等待遇（都是本系统记录的事实，不是模型
写的句子）。优先级：追问自己写了时间 > 读者手动指定 > 沿用会话。沿用**不**升级成硬过滤，
并带标签「沿用对话 · …」显式可见。

取最近一轮而非最早一轮，否则「那上个月呢」会被采纳一次然后被开场那问永远压过去；
没解析出窗口的轮次跳过而不是当成「全部时间」，否则一个没写日期的追问会抹掉整段会话的范围。

## 六、过拒的修复过程与当前状态

被删掉的原句（`uncited_examples` 记录）：

```
检索到的内容里没有提到 gemma-4 的 coder 和 coderx 两个量化版的具体区别。
证据中只出现了 v7-coderx 和 v6-coder 的对比，没有 coder 与 coderx 的直接比较。
```

两题都标注 `answerable: true` 且各有 2–3 条相关文档，**材料确实在语料里**——
模型两侧都找到了，然后拒绝把它们并排放。原因是提示词规则 9：

> 问题要求的直接关系…若不在证据中，即使证据提到同一模型的其他事实，也属于证据不足…
> 不要用邻近事实拼成一个看似回答的列表。

这条规则是为了挡住「拼凑邻近事实」（智谱那次的真实失败）。但**对比题的证据天然就是
一篇讲 A、一篇讲 B**，规则 9 等于告诉模型这不够。门禁里两道误拒全是 comparison。

| 版本 | over_refusal_rate | 状态 |
|---|---|---|
| 基线 | 0.0256 | 034 + 044 都拒答 |
| **v7**（规则 9 给对比题开口子） | **0.0128** | 044 通过；**最后一次有效测量** |
| v8（自检加一条） | — | 未测（见下） |

v7 之后 034 仍然拒答，模型改写成了：

```
证据中只出现了 v6-coder 和 v7-coderx 的对比，其中 v7-coderx 是 Gemma-4 26B-A4B MoE
剪枝到 98 个专家（约 20.8B 总参数、约 4B 激活）的推理模型，而 v6-coder 是同一架构的
coder 版本，但证据没有说明两者在量化上的差异。
```

参数量、专家数都能在语料里查到，是真事实——但整句被框成「证据里缺什么」，所以一个编号
都没带，整句被删，事实和结论一起丢。v8 针对这个形状：证据说过的单独成句并标注编号，
缺什么另起一句。

## 七、v8 没测成：DeepSeek 余额耗尽

`over_refusal_rate 1.0`、原因栏全是 `unrecorded`。**乍看和「本次改动把流水线搞崩了」
完全一样。**

这正是 `refusal_cause` 要防的事，而生成失败那条路径恰恰漏了标签。已修：

- 该路径打 `generation_unavailable`
- 评测检测到这种失败时直接标 `run_valid: false` 并写明原因，不再把一次停机当成一次测量
