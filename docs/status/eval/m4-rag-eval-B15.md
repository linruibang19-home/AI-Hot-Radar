# B15 稀疏通道 IDF 加权 + 实体词加权：负结果

`eval_run_id`：见 [m4-rag-eval-B15-20260809.json](m4-rag-eval-B15-20260809.json)
对照：[B14-20260809](m4-rag-eval-B14-20260809.json)

被测改动（阶段 B-1）：
1. 稀疏通道排序由 `ts_rank_cd` 换成 **IDF 加权重叠**（`sum(ln(N/df))`）；
2. 属于语料 `entity` 表的词项 **×3 加权**。

两条都针对同一个实测失败：问「智谱最近发布了什么」答「智谱没有发布任何东西」，
而窗口内有三条智谱内容。

## 结果

| 指标 | B14 | B15 | Δ |
|---|---:|---:|---:|
| Recall@10 | 0.8444 | 0.8509 | +0.0065 |
| Recall@20 | 0.8887 | 0.8908 | +0.0021 |
| MRR | 0.8690 | 0.8720 | +0.0030 |
| nDCG@10 | 0.8102 | 0.8148 | +0.0046 |

**四项全升，而且四项全部落在 B14 测出的 ±0.02 噪声底以内——所以这不是提升，是测不出来。**

90 题里 5 题变化：

| 题号 | Δ R@10 | 读法 |
|---|---:|---|
| RAG-GOLD-090 | **+1.000** | **已知漂移**：它在 B14 里以逐字相同的输入掉了 −1.000，这一轮弹回来 |
| RAG-GOLD-020 | +0.250 | 可归因：B14 里被别名扩展稀释掉的那题，实体加权把它救回来了 |
| RAG-GOLD-031 | −0.333 | 未归因 |
| RAG-GOLD-019 | −0.250 | 未归因 |
| RAG-GOLD-001 | −0.167 | 未归因 |

把已知漂移的 090 剔掉，净变化是 −0.50/78 = **−0.0064**；算进去是 +0.0065。
**同一份数据按两种同样合理的读法给出相反符号，这就是"测不出来"的定义。**

## 为什么会这样：B8 的结论再次成立

B8 记过：融合前的指标是会骗人的优化目标，因为**交叉编码器会重写融合序**。
稀疏通道的排序正是融合前的东西。我在写这一轮时把 40 条候选的顺序调得更合理，
而重排器把它们重新排了一遍——两个不同的输入序收敛到同一个输出序。

**这是我这一轮实际犯的错误**：连着两次单独观察稀疏通道的前 6 条来判断改动好不好，
而那个视图与读者拿到的答案之间隔着一整个重排阶段。项目在 B8 已经付过一次学费。

## 智谱那条为什么仍然没修好——它根本不是排序问题

逐层追下来，真正的原因不在稀疏通道：

```
「GLM-5.2 量化模型发布：混合精度专家与融合 MoE 优化」   ← 目标文档
```

**这篇文档里根本没有「智谱」这两个字。** 查询最强的词项（`智谱`，idf 7.66，
加权后 22.98）在目标文档里**命中不了**；能命中的只有别名 `glm`（idf 3.87）。
而一篇顺带提到「智谱」的行业综述能拿到全额 22.98。

**关键词检索按定义就该这样排**——「提到 X」和「讲的是 X」的区分不归它管，
那是稠密通道与 `directness` 维度的职责（B9 建它正是为此）。
所以继续调稀疏权重是在错误的层上使劲。

### 下一步该验的假设（写下来以便证伪）

失败可能出在**别名的语义强度**上：`智谱` 与 `GLM-5.2` 在 bge-m3 的向量空间里
未必接近，而扩展只把 `GLM` 加进了**关键词**通道，没有影响稠密通道。
可验证的做法是把扩展后的实体名加进**嵌入输入**（改写查询再嵌入），
而不是只加进 tsquery。这需要一轮独立评测，且必须端到端看，不能再看通道内的前 6 条。

## 保留还是回退

**保留。** 两条改动各自有独立成立的理由——`ts_rank_cd` 没有 IDF 是 ADR-0015 就记下的
已知缺陷，实体词与偶然 bigram 同权是本轮量出来的（`了什` df=18、`布了` df=23，
在以英文为主的语料里，任何中文 bigram 都天然稀有，df 天花板对它们无效）——
而端到端测不出负面影响。

但**不得声称它们带来了提升**：账面上的 +0.0065 在噪声底以内，
唯一可归因的正向变化是 RAG-GOLD-020 那 +0.250，而它抵消的是我自己上一轮引入的退化。
