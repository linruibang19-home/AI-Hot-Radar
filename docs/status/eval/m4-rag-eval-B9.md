## 两个维度各自在修什么

### `directness`：这篇文档**是**讲这个的，还是**提到**了这个？

B1 发现、B2 只部分修好的那个失败。问「使用 MXFP4 量化的是哪个模型」，
排在正确答案前面的是：

```
vLLM v0.26.0 发布           ← 某条 bullet 里提到 MXFP4
Kimi K3：2.8T 参数与 MXFP4 量化   ← 整篇就是讲它
```

两段正文都含这个 token，稀疏检索也都能命中。区别在于**标题**：
一份 release note 顺带列出支持的格式，和一篇主题就是该模型的文档，
对「哪个模型用了它」这个问题的回答力度完全不同。

所以 `directness` = 问题词项在**文档标题**中的覆盖率。
刻意不算正文——正文正是交叉编码器已经打过分的东西，再算一遍是把 relevance 重复计分，
而不是增加一个维度。

`timeline` 类涨 4.45 点最多，符合这个机制：时间线问题都点名了具体主体。

### `source_fit`：这类信源答不答得了这类问题？

本语料是 53 个 GitHub Release + 媒体 + 专家 Newsletter。
一份 changelog 是**一手信源**，同时也是「解释一下 MoE 路由是什么」的**糟糕证据**——
它在陈述，不在解释。只看相关性看不出这个差别，因为两者确实都在讲这个主题。

亲和度表里 `explainer` 是唯一一行有负值的（primary = −0.3），这正是它存在的意义。
实测 `explainer` 的 R@10 涨 3.34 点。

## 三个刻意的约束

1. **加在交叉编码器之后，不加进融合。** B8 刚证明重排会重写融合序，
   所以一个需要活到最后的信号必须加在重排下游。
2. **幅度受限**：两维合计上限 0.18，加在归一化到 [0,1] 的相关性上。
   B3 第一版把 ±0.05–0.15 加在跨度只有 0.008 的原始 RRF 分上，
   元数据静默变成了排序函数——这条教训是有代价换来的。
3. **未知信源等级记 0，不扣分。** 缺失的等级是缺失的信息；
   当成坏信源会把加工尚未覆盖到的内容悄悄压下去。

## 写这个模块时踩到的一个坑

第一版 `tokenize` 写了 `MIN_TERM_CHARS = 2` 过滤掉单字符 token，
用意是滤掉标点和英文冠词。而**中文按字切分，每个 token 就是一个字**——
这条规则把中文全删了，`directness` 会对**每一道纯中文问题稳定返回 0.0**，
而且不会报任何错。

B2 撞过同一形状的问题：稀疏通道对 15 道纯中文题零命中。
现在长度下限**只对拉丁字母生效**，并且有一条专门的用例锁住它。

## 顺带修掉一个更严重的问题：B7 根本没上线

写这一轮的接线时发现，**B7 的 `temporal_fit` 评测跑过、报告写过、状态标成已完成，
但从未接进 `service.py`**。`recent_updates` MRR 0.6484 → 0.7522 那个提升
只存在于评测框架里，真实的 `/rag/ask` 从来没有用上。

文档描述的是一个读者从未收到过的配置。**评测如果不绑定线上路径，它就是新闻稿。**

已一并接入，并加了两条用例锁死：
线上 `retrieve` 必须调用这两个函数，且必须在**未重排的尾部拼接之前**调用——
加在合并后的列表上会连交叉编码器没打过分的候选一起重排，
那是 B7 和 B9 都没有测过的配置。

## 已知局限

- `directness` 是词项覆盖率，不是语义蕴含。标题用同义词改写（「开源」/「开放权重」）
  它认不出来，这跟聚类当前缺 Embedding 特征是同一个缺口。
- `SOURCE_AFFINITY` 的数值是按语料结构定的，**没有单独做网格调优**。
  按 B8 的结论，这类小幅调参的预期收益低于测量噪声。
- 未实现 §6 的另外两条 boost：「直接命中目标实体为主语 +0.05」需要实体角色标注，
  「重复转载 −0.10」需要转载关系，两者当前都拿不到。
