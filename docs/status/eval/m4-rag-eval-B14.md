## 由此得到的方法论结论：跨日对照有约 ±0.02 的噪声底

`snapshot_window` 钉住的是**条目**（两轮都是 915 条），钉不住**索引**。
两轮之间语料从 6304 涨到 6323 个分块，而 **HNSW 是近似最近邻**：
往图里插入向量会改变遍历路径，与新内容毫不相关的查询也可能换回不同的邻居。

**所以 B 轮之间小于约 0.02 的 Recall@10 差异不能当作结论。**
回头看这条对既有历史同样成立：B9 → B10 的 +0.0058、B12 → B13 的差异，
都落在这个噪声底以内。项目在生成侧已经记过同一现象
（「72 题代码路径逐字未变仍动了 −2.0pt」），这一轮是它在检索侧的对应物，
而且这次能逐题证明。

要做到干净的 A/B，必须**同一时刻、同一索引**跑两个配置，
而不是隔两天跑两轮。这需要评测支持在一次进程内跑多个变体，已记为待办。

## 唯一确定的一条代码退化

`RAG-GOLD-020`（「DeepSeek V4-Flash 从发布到被产品接入」）R@10 1.000 → 0.750，
原因是 `DeepSeek` 扩展出 `DeepSeek V4 Flash` / `DeepSeek-R1` / `DeepSeek-V3` /
`DeepSeek-V4` 四个版本名。这题问的是**某一个具体版本**，把兄弟版本一并 OR 进去
是在稀释它。

这与智谱那条失败是同一枚硬币的两面：**别名扩展对「厂商级」提问有用，
对「具体版本」提问有害**。当前实现不区分，代价是一题 −0.25，收益是一类失败模式
（问 `智谱` 找不到 `GLM`）在生产上被关掉——而后者目前**还没有黄金题覆盖**，
所以这一轮的账面只看得见代价、看不见收益。

**下一轮该做的不是回退，是补题**：黄金集需要「用中文厂商名问、答案文档只用英文
产品名」这一类，否则评测系统性地低估这个改动。已记为任务卡。
