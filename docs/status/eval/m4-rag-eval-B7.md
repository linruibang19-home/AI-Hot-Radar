# B7 时效融合：把 B4 唯一的退化补回来

逐题数据：[B7](m4-rag-eval-B7-20260804.json) ｜ [B4 对照](m4-rag-eval-B4-rerank40-20260804.json)
实现：`rag/temporal.py`

## 为什么做这个

B4 的重排在**五个类别上大幅提升**，只有一个退步：

```
recent_updates MRR   0.7333 (B3)  →  0.6484 (B4)   −8.5pt
```

原因不含糊：**交叉编码器不知道时间**。「Cloudflare 最近有什么新动作」里没有任何东西
告诉它今早的发布优于三周前同样相关的一条，而对资讯产品来说**新近本身就是相关性的一部分**。

`AHR-RAG-400` §6 列了 reranker 应产出的四个维度——
`relevance` / `directness` / `temporal_fit` / `source_fit`——托管的交叉编码器只给第一个。
这一步补上 `temporal_fit`。

## 设计上刻意约束的两点

**① 权重是少数份额（0.30）。** 相关性仍然主导，一条"只是新"的段落不能压过
真正回答问题的那条。这条约束是有代价教训的：第一版 B3 把 §6 的 boost 直接加在
原始 RRF 分上，而 boost 幅度是被加数跨度的 5–10 倍，**元数据静默变成了排序函数**，
`fact_check` 的 Recall@10 从 0.9556 崩到 0.2556。

**② 无时间语义的问题完全不碰。** 「NEO-Unify 架构是怎么工作的」按发布时间排序，
会把这个架构的最新一次提及排到解释它的那篇文章前面——那不是次优，是错的。
上表里五个类别的 +0.0000 就是这条约束的直接证据。

## 实现细节

- **新近度按窗口归一，不按绝对半衰期**。读者问的是一个区间，
  所以"新"应该是**相对这个区间**的新：7 天窗口和 30 天窗口都应把内容铺满整个值域，
  而不是其中一个塌缩成单一值。
- **缺发布时间的条目取 0.5**——既不因信源没写清楚而被提拔，也不因此被惩罚。
- **相关性分数全相同时归一化为全 1.0 而非全 0**。交叉编码器打平分很常见，
  塌缩成 0 会把整个决定权交给新近度。
- 并列按 key 排序，保证两次评测不会因为无关原因产生差异。
