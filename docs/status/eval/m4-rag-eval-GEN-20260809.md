## 下降的三项：两项是机械后果，一项是抖动

**① citation coverage −5.47pt、story coverage −2.50pt：机械后果，不是退化。**
门控移除引用，带引用标记的句子自然变少、被引事件自然变少。
平均引用数 3.90 → 3.59 是同一件事的另一种表述。
这是**用覆盖面换取可信度**的显式交易：留下的每一条更可能真的支撑它所配的论断。

**② must_contain 1.0000 → 0.9545：一道题，且与门控无关——有跨轮证据。**
逐题比对只有 `RAG-GOLD-016`（timeline）掉分，**而它的引用数 3 → 3 没有变化**，
门控没有从这道题移除任何东西。翻出全部五轮它自己的读数：

| 20260804 | 1.00 | 3 |
| 20260807 | 1.00 | 3 |
| **20260807-judged** | **0.00** | 3 |

总体读数同样在抖：0.9091 / 0.9545 / 0.9091 / 1.0000 / 0.9545。

## 补测：两个口径并列量了一轮，同义反复被实证了

`eval_run_id`：`GEN-20260809T041225Z`
逐题数据：[m4-rag-eval-GEN-20260809-dual.json](m4-rag-eval-GEN-20260809-dual.json)

上一节指出线上与离线打分喂的文本不同。这一轮把**两个口径同时算出来**
（`support_*` = 被引段落，`support_as_read_*` = 模型读到的父块），结果是决定性的：

| 口径 | 均值 | 达标率 |
|---|---:|---:|
| 父块级（**门控自己的口径**）| 0.9065 | **1.0000** |
| 段落级（门控**没有**强制的量）| 0.8429 | **0.9371** |

**父块级达标率是 1.0000，而这恰恰说明它不能当判据。**
门控只放行父块级达标的引用，所以这个数**只能报告门控自己放行了什么**——
它是同义反复，不是测量。这与 ADR-0020 记的 abstention 是同一个陷阱的另一面：
**一旦拿某个数去做门控，那个数就不再是测量。**

段落级是还能失败的那个，因此 [ADR-0021](../../adr/0021-citation-correctness-is-entailment-not-annotation-overlap.md)
把 `citation correctness` 的判据定在它上面。**实测 0.9371 ≥ 0.90，这条门禁通过。**

### 顺带证实了 must_contain 的抖动判断

本轮 `must_contain_hit` 回到 **1.0000**，`RAG-GOLD-016` 也回到 1.00。
加上前一节的五轮表，这道题的读数序列是 1 / 1 / 0 / 1 / 0 / **1**，引用数恒为 3。
**它就是会翻。** 同轮 `refusal_rate_on_unanswerable` 也从 0.0000 跳到 0.0833——
按 ADR-0020 这个量已不作判据，但它同样说明**这批指标在 90 题上的轮间噪声是几个百分点量级**，
小于这个幅度的差异不能当结论。

## 关于「无引用存在但不支持结论的 P0」这一条

规格原文是「**关键问题**无『引用存在但不支持结论』的 **P0 缺陷**」。
这是一条**定性**判据——它要求的是对关键问题做人工核对后没有 P0，
不是要求全语料的低分率归零。此前把它记成「0 例」是我读严了，已更正。

定量代理是段落级 `support_supported` = **0.9371**（ADR-0021），
仍有 **6.29%** 的引用在段落级低于阈值。**定性那一半尚未做**：
需要挑一批关键问题人工核对被引段落是否真的不支持论断，已列为任务卡。

低分残留不是门控漏判，而是**线上与离线给同一条引用打分时喂的文本不是同一段**：

| | 打分输入 | 代码 |
|---|---|---|
| 线上门控 | **父块展开后的文本** | `service.py`：`{e.chunk_id: e.text ...}`，而 `e.text = parent.text[:MAX_PARENT_CHARS]` |
| 离线评测 | **裸分块正文** | `eval/generation.py::_load_context`：`SELECT ch.body_text` |

一条论断可能被父块里的相邻段落支撑、却不被命中块本身支撑：
线上放行，离线判不达标。**两个数因此不可直接比较。**

`support.py` 的模块注释写着「与离线评测用同一个方法，否则页面上的数和报告里的数就不可比」——
**方法确实相同，输入不同，所以那句话目前只兑现了一半。**

这不是一个可以顺手改的选择题，两种口径各有道理：

- **父块口径**回答「模型读到的证据是否蕴含它的论断」，这是 §10 的字面问题；
- **分块口径**更严，接近「读者点开这条引用能否当场核对」，是产品主张的那个问题。

因此这里**只记录不改**，并列为下一张任务卡：统一口径要么改评测、要么改门控，
无论哪边都必须重跑这一轮才能和本报告比较。在统一之前，
`support_supported` 的两个数值必须**标注各自的口径**，不能混着引用。

## 结论

- 门控达到了它的目的：目标指标 +9.94pt，`abstention` 类 +35.1pt；
- 设计时刻意加的两条约束（只移除不拒答、永不清空引用列表）被数据证实是必要的——
  误拒率与断言假前提率保持 0.0000；
- 代价是覆盖面下降 2.5–5.5 个点，是显式交易而非缺陷；
- **门禁 #9 从「13.98% 未达标」降到「4.04%，且只剩 1 道题」，但没有归零**，
  剩余部分由打分口径不一致解释，已记为待办。
