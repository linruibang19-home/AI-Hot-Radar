## 4. 标准发布流程

1. 在 `codex/<task>` 分支完成单一任务卡并运行任务相关门禁；
2. push 分支、创建 PR，等待 CI 全绿后合并 `main`；
3. 为合并提交创建 `v*` 标签，Release workflow 重跑全量门禁并发布三张 SHA 镜像；
4. 服务器 `production` 仅 fast-forward 到 `origin/main`，把 `IMAGE_TAG` 改为该合并提交的
   `sha-<40 hex>`，运行 `infra/scripts/deploy-production.sh`；
5. 复验 HTTPS、核心页面、RAG、邮件、monitor 与备份年龄。失败则回退上一 `IMAGE_TAG`。

不要在服务器直接改业务代码，也不要从开发机复制 `.env`。GitHub 是代码事实源，服务器
只保存生产配置、数据卷、备份和当前不可变镜像选择。
