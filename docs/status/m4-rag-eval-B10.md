## 两条各自在修什么

### `entity_subject` +0.05：主语 vs 提及

一篇发布说明的**主语**是被问的那个模型，它回答了问题；
另一篇在「支持的格式」列表里**提到**它，只是提及。
`item_entity.role` 早就把这条线画好了，只是没人用它排序。

`timeline` 与 `recent_updates` 涨得最多，符合机制：这两类问题几乎总是点名一个主体
（「llama.cpp 最近…」「Qwen 的发布顺序…」），而语料里关于该主体的文档很多，
真正**以它为主语**的是少数。

与 B9 的 `directness` 有关但不重合：`directness` 看标题词面覆盖，
`entity_subject` 看结构化抽取出的语义角色。两者常常一致，但不总是——
标题写「三家发布对比」而主语是其中一家时，只有后者能分辨。

### `repost` −0.10：降权而不是排除

**516 个分块挂在近似重复条目上**——它们在被判定为重复**之前**就已经切好块进了索引。
所以转载内容确实在检索结果里，这条惩罚有真实工作可做。

选择**降权而非排除**：原文和副本各自独立参与排序，副本排上来时原文未必也在候选集里。
把副本删掉可能等于删掉唯一的证据。

## 实体解析：用语料自己的词表，不跑 NER

问句 → 实体 id 的解析直接匹配 `entity` 表，而不是另跑一个 NER 模型。理由是
**能影响排序的实体只可能是语料已经认识的那些**，而这张表恰好就是那份名单；
副产品是不需要维护两个模型之间的一致性。

分词沿用与 `dimensions.py` 相同的双语规则：**CJK 子串匹配（≥2 字）、拉丁词边界匹配（≥3 字符）**。
长度下限是必需的——语料里真有名为 `ai` 和 `X` 的实体，
不设限的话每一道提到 AI 的问题都会命中它们。实测：

```
使用 MXFP4 量化的是哪个模型？        → MXFP4
Anthropic 那次测试…                  → Anthropic
llama.cpp 最近发布了哪些版本？        → llama.cpp, LLaMA
最近有哪些新动态？                    → （空）
什么是 MoE 路由？                     → MoE
```

## 已知局限

- 实体解析是**字面匹配**，别名与改写认不出（「谷歌」/「Google」若在库里是两个实体则只命中其一）。
- `repost` 只覆盖 SimHash 判定的 `NEAR` 重复，跨语言转载（英文原文 + 中文编译）认不出。
- 增益幅度小（总体 +0.58pt R@10），单看总分接近噪声；
  说它有效的依据是**方向一致且无一项退化**，以及两个目标类别各涨 1.3–1.7pt。
