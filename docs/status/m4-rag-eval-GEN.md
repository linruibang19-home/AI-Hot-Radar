`eval_run_id`：`GEN-20260804T060558Z`
逐题数据：[m4-rag-eval-GEN-20260804.json](m4-rag-eval-GEN-20260804.json)
方案：[design/m4-rag-evaluation.md](../design/m4-rag-evaluation.md) §5.5

检索侧四轮（B1–B4）看不见生成的任何东西。B5 父块与 B6 折叠尤其如此——
它们改变的是**模型读到什么**和**读到哪些来源**，不改变排序，
所以无论它们工作正常还是彻底坏掉，Recall 与 nDCG 一动不动。这一轮补上这个盲区。

## 这一轮抓到的真缺陷：1.4% 的内容对检索完全不可见

引用精度最低的题里，RAG-GOLD-049 是 **0.00**，值得单独追。

```
问：哪个模型发布了 NVFP4 量化版并支持 vLLM？
标注答案：Qwopus3.6-27B-Coder 发布 NVFP4 量化版，支持 vLLM 与工具调用
实际回答：「NVIDIA Ising Calibration 1.5」——一个量子计算机校准工具
```

B1 测这题是 Recall@20 = 1.00、排名第 1，所以不是检索不行。逐层追：

```
检索后：命中 83 块，目标文档出现在第 [] 位   ← 根本没进结果
选证后：10 条，目标文档【已被丢弃】
```

查该文档当前状态：

```
2717b0e9… | maci0/Qwopus3.6-27B-Coder-NVFP4 | 是重复=f | 无版本=f | 分块数=0 | 已向量化=0
```

**它被重新采集过，生成了新的 `current_revision`，而新 revision 从未被切块。**
标题也从加工后的中文标题退回成了原始仓库名，佐证了这一点。
分块数为 0 意味着它在索引里不存在——检索**不可能**找到它，
而模型只能在剩下的证据里挑一个最像的，于是挑了个量子计算工具。

全语料范围：

| | 条目 | 占比 |
|---|---:|---:|
| 有分块 | 1017 | 98.6% |
| **零分块（不可检索）** | **14** | **1.4%** |

黄金集 127 个标注 item 里有 1 个处于这个状态。

### 守卫已补

`verify_items_exist` 原来只验「存在 且 非重复 且 有 current_revision」，
**没验有没有分块**——所以它放行了一个不可能被检索到的标注，
把一次流水线故障伪装成了检索质量问题。现在三项一起验：

```
$ ahr rag-eval --validate
{"error": "annotated items not usable", "items": ["2717b0e9-…"]}
```

这类"看起来像 A、实际是 B"的故障，本轮已经是第三次：
`asked_at` 早于语料最新时间伪装成检索退化、`temporal` 漏权重伪装成融合失效、
现在是流水线漏切块伪装成引用精度低。**每一次都是评测把它们从直觉里挖出来的。**

## 未解决

- **零分块条目本身没修**。1.4% 的内容重新采集后停在了未切块状态，
  需要查 `pipeline` 为什么没有覆盖它们——这是采集/加工链路的问题，不属于 RAG。
- **`must_not_claim` 仍只做子串匹配**。12 道不可答题里 4 道被标记"提及禁词"，
  但其中至少 3 道是**否认**（「证据中未涉及 Qwen4-Ultra」），不是断言。
  这个指标只能作为人工复核的入口，不能作为判定。
- **拒答率 0.6667 有解释但没定论**。未拒答的 4 题里，模型给出的是
  「检索到的内容里没有提到 X」并引用了它核查过的证据——行为正确，
  但按当前口径不计为拒答。需要区分「拒答」与「有据可依的否认」，
  这需要更细的判据，不是调阈值能解决的。
- support_threshold = 0.30 仍未标定。
