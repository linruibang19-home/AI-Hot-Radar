## 5. 最终逐句发布门禁

全量生成首次实跑暴露 4 题在支持度删除引用后留下无引用句。根因是逐句检查执行过早。
修复后顺序固定为：支持度评分 -> 删除弱引用 -> 删除所有无服务端引用的事实句 ->
移除孤儿引用并重编号 -> 无事实/无引用则拒答 -> 不变量校验。

`RAG-GOLD-009/013/028/036` 用真实 embedding、rerank、LLM 逐题重放，引用完整性均为
1.0000，支持度门禁均通过。没有重新花费一次完整 90 题生成预算；全量指标来自修复前的
真实生成轮，顺序修复由 77 个专项测试和四题真实重放覆盖，报告中不把两者伪装成同一次 run。

## 6. 剩余风险

1. `RAG-VENDOR-014` 的目标原文稳定在第 27 名；后续可在不增加在线 LLM 往返的前提下，
   扩充针对“托管服务 + SLA + 模型号”的稀疏召回训练/标注。
2. 自动 citation precision 依赖稀疏黄金标注，只作为诊断；不能把未标注但正确的原文算成
   生产错误，也不能用该限制取消人工 P0 审计。
3. 90 题全量重排耗时 522081 ms，生成平均 8884 ms；性能长尾由下一任务卡单独处理，
   本卡不把更多候选或额外查询改写上线。
4. Planner 的 query-type 代理不具操作性；若规格不改，应新增独立的实体解析与时间窗
   人工标注集，而不是把评测 category 回填成答案。
