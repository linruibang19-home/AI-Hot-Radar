## 1. 第一个决定：服务器放哪里（这条决定其他所有事）

**中国大陆服务器 + 域名对外提供服务 = 必须 ICP 备案。** 备案周期通常 1–3 周，
且要求服务器是大陆节点、提供身份证与人脸核验。对一个求职作品来说，这个周期
往往比项目本身的剩余工作还长。

| 方案 | 备案 | 面试官访问体验 | 月成本估算 |
|---|---|---|---|
| **A. 阿里云香港 / 新加坡轻量应用服务器** | **不需要** | 大陆访问略慢，Cloudflare 代理后可接受 | ¥24–70 |
| B. 阿里云大陆 ECS | **需要，1–3 周** | 大陆最快 | ¥60–100 |
| C. Vercel + 托管数据库 | 不需要 | 快 | 需拆分架构，见 §5 |

**建议 A。** 理由不是省钱，是**去掉一个 1–3 周的、不由你控制的阻塞项**。
简历投递有时间窗，备案审核没有。等作品跑起来、拿到面试之后再补备案迁大陆也不迟。

## 2. 服务器规格

七个容器，实测占用：

| 服务 | 内存 |
|---|---|
| postgres + pgvector（库 203 MB） | ~400 MB |
| core-api（Spring Boot / JVM） | ~500 MB |
| web（Next.js standalone） | ~200 MB |
| ai-service + scheduler + pipeline（Python × 3） | ~450 MB |
| redis | ~30 MB |

**峰值约 1.6 GB，加上构建与系统开销，最低 2 GB，推荐 4 GB。**

> **2 GB 机器上不要在服务器上构建镜像。** `next build` 与 Maven 编译会瞬间吃满内存
> 触发 OOM。做法见 §4：在 GitHub Actions 构建、推镜像、服务器只拉取运行。

磁盘 40 GB 起步：原始 HTML 目前占库体积约一半，且随采集线性增长。

## 3. 网络与 TLS

```
访问者 → 源站 :443 → Caddy → web:3000
                               └→ core-api:8080（仅内网）
                               └→ ai-service:8000（仅内网）
```

- 当前 Caddy 直接终止 TLS 并自动申请证书。未来若增加 CDN，必须使用等价于
  **Full (strict)** 的源站验证；不得使用到源站明文的 Flexible 模式。
- **只暴露 80/443**。`core-api`、`ai-service`、`postgres`、`redis` 全部不映射到宿主机端口——
  它们现在为了本地开发才映射的，上线必须去掉。
- 用 **Caddy** 而不是 nginx：两行配置自动签发与续期，本项目没有需要 nginx 的复杂路由。

## 4. 部署流水线

GitHub Actions 构建 → GHCR 推镜像 → 服务器 `docker compose pull && up -d`。

理由：2 GB 机器构建会 OOM；而且**构建产物与代码提交绑定**，回滚就是拉上一个 tag。

已实现：生产 Compose 不映射内部端口；release 先验证同一提交再构建三镜像；Caddy 自动
TLS；部署只接受不可变 `sha-<40 hex>` 标签。`preflight.sh`、`deploy-production.sh`、
`smoke-production.sh` 把配置、发布和公网验收串成失败即停的门禁。

## 5. 为什么不用 Vercel

Vercel 只能跑 `web`。`core-api`（JVM）、三个 Python 服务、Postgres+pgvector 都要另找地方，
一个项目拆到三个平台，**部署复杂度反而高于一台 4 GB 的机器**。
本项目是长驻 worker 架构（scheduler 每 120s、pipeline 每 900s），Serverless 天然不合适。

## 6. 上线前必须做的四件事

1. **轮换全部密钥** —— GitHub PAT、DeepSeek、硅基流动、Postgres 口令。
   它们出现在过开发会话记录里。生产用**新密钥**，不要复用本地的。
2. **去掉内部端口映射**（见 §3）。
3. **数据库备份** —— `pg_dump` 每日 + 保留 7 天。作品挂了可以重启，
   数据没了要重新采集好几天。
4. **成本闸门** —— DeepSeek / 硅基流动都设消费上限。`/ask` 是公开的，
   一次爬虫扫站就能把额度打空。

生产 monitor 可复用报告投递 SMTP 向 `ALERT_EMAIL_TO` 发送故障与恢复通知；也可配置
Slack-compatible `ALERT_WEBHOOK_URL`。两个通道均配置时都会尝试，预检要求至少一个真实
告警目的地，避免为了单机作品站再强制引入一个通知平台。

## 7. 面向面试官的收尾（这决定作品的说服力）

- 首页加一句**「这是什么、数据从哪来、多久更新一次」**，面试官不会先读 README。
- `/ask` 页面预置几个**能立刻看出效果**的问题（现在示例已删除，上线前应按当时语料补回）。
- README 顶部放：**在线地址 + 一张截图 + 三行技术亮点**（混合检索、可回原文的引用、拒答）。
- 保留 `docs/status/` 的十轮评测报告并在 README 链接过去——
  **有数字的项目和没数字的项目，在面试里完全是两回事。**
