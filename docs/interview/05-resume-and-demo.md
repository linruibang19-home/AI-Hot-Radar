# 05｜简历表达与现场演示

## 1. 简历项目标题

**AI Hot Radar｜可追溯 AI 行业情报与时效 RAG 平台**  
Next.js · Spring Boot · FastAPI · PostgreSQL/pgvector · Redis · Docker Compose

## 2. 三条简历 bullet（事实版）

- 设计并实现 140 信源的增量采集与内容加工管线，覆盖全文回源、幂等去重、LLM schema 校验、
  事件聚类、精选评分及日/周/月报告，并以 PostgreSQL 作为唯一事实源、Redis 仅承载缓存和限流。
- 构建 pgvector + PostgreSQL 全文检索 + 时间/实体约束的混合 RAG，经交叉编码器重排、证据折叠、
  父块展开和服务端引用绑定，在固定 90 题发布集达到 Recall@20 89.9%、句级引用覆盖 98.8%，
  可答题误拒 0/78、诱导题错误断言 0/12。
- 完成 2C4G 单机生产闭环：不可变 SHA 镜像、Caddy HTTPS、管理 RBAC/审计、SMTP 双确认订阅、
  备份恢复与告警；保留检索负实验与逐题结果，并将质量门、成本和信源状态产品化展示。

数字必须保留“固定发布集/特定快照”等限定语。答辩前重新确认线上服务与测试总数。

> 我做的是一个 AI 行业时效情报平台。它从 140 个公开信源持续采集正文，经过幂等去重、
> 结构化、事件聚类和精选评分，产出网站与日周月报；在同一份可追溯语料上提供时间感知 RAG。
> 我最想展示的不是调用了模型，而是 90 题发布门禁、每次检索轨迹和服务端引用绑定：
> 我保留了三轮负实验，也有一次原先的根因判断被下一轮原始响应证伪。最后把它部署在 2C4G
> 单机上，做了 HTTPS、备份恢复、告警、模型切换和邮件订阅闭环。

## 4. 五分钟演示脚本

### 0:00–0:40：一句话价值

打开 `/ask`，用预置问题提问。强调“所有回答只基于站内采集语料，每句话可点回原文”。

### 0:40–1:40：引用与检索解释

点引用编号到来源卡，展开“为什么是这些证据”。展示 dense/sparse 名次、重排、同事件折叠和淘汰原因。

### 1:40–2:20：不可答与安全

提一个带假前提的问题，展示有引用的否认；说明引用 URL 不由模型生成，编号越界会被剥离。

### 2:20–3:20：质量门

### 3:20–4:10：内容产品

打开 `/reports` 与邮件订阅：报告只发送 `PUBLISHED` 快照，邮箱必须双重确认，失败不阻塞站内发布。

## 5. STAR 故事素材

### 故事 A：解析器导致误拒

- S：生成侧可答题误拒从 1.28% 升到 7.69%。
- T：判断是检索退化、模型退化还是解析/校验问题。
- A：先记录“语料增长导致竞争”是假设；下一轮抓六道题原始响应，发现答案和引用都在，
  只是 JSON/claims 契约偶发偏离；实现带守卫回退且不放松校验。
- R：误拒降到 0%，诱导题错误断言仍为 0；更重要的是证伪了自己原先的合理猜测。

### 故事 B：跨服务限流接缝

- S：匿名用户看似按 IP 限流，实际 Next 未转发 `X-Forwarded-For`，全站共用一个桶。
- T：定位为什么两个服务各自单测都绿但生产行为错误。
- A：沿请求链检查每一跳的 header 契约，在代理接缝加测试并限制可信代理边界。
- R：恢复按真实客户端粒度限流；形成“跨服务契约必须在接缝测试”的规则。

### 故事 C：信源状态机恢复

- S：一次 DNS 抖动把多个一手源直接隔离且无法恢复。
- T：让失败阶梯与规格一致，同时保留可观测性和人工干预。
- A：恢复连续失败的 DEGRADED/QUARANTINED 阶梯，加入 probe 和审计，而不是单次失败即封禁。
- R：一手源恢复，状态变化可在信源后台解释。
