# 04｜面试问题库

每题先用一句话给结论，再补证据、取舍和边界。不要把下面答案背成广告词。

## 产品与业务

### 1. 为什么不就是一个新闻聚合站？

聚合只是入口。核心差异是正文质量门、跨源事件聚类、报告发布快照和可回到原文证据的 RAG；
工程页面还公开检索负结果与运行成本。

### 2. 用户最核心的闭环是什么？

发现高价值动态 → 按事件或主题阅读 → 在报告中快速消费 → 对细节提问并点回原文核验 →
通过邮件按周期接收已发布报告。

### 3. 如何衡量产品而不只衡量模型？

内容侧看新鲜度、全文率、重复率、跨源 Story 率和精选点击；RAG 看答案成功、引用点击、追问、
拒答与反馈；订阅看确认率、送达率、退订率。模型指标只是其中一层。

## 数据与后端

### 4. 如何保证重复采集不产生脏数据？

规范 URL、内容哈希、业务唯一键和事务 upsert；处理任务基于 revision 与 pipeline version 幂等，
报告投递再用订阅+报告唯一事实防重复。

### 5. PostgreSQL 为什么是事实源？

内容、状态机、发布、检索轨迹和投递都需要事务一致性；Redis 可以丢、可以重建，不承担真相。

### 6. 为什么没有 Kafka？

当前单机、低吞吐，没有必须独立扩缩容且对重放有硬要求的消费者。轮询和数据库锁更简单；
`outbox_event` 目前没有消费者，不应包装成“已经实现事件驱动”。

### 7. 外部 API 故障怎么办？

设置 connect/read timeout、有限重试、指数退避、per-host 限流和 trace id；模型不可用时保留原文，
已有内容继续服务；邮件失败不阻塞发布。

## RAG

### 8. 为什么同时要 dense 和 sparse？

自然语言改写与精确型号是两种召回问题。真实题中正确证据 dense 第 14、sparse 第 1，融合后第 3。

### 9. 为什么 RRF，不直接加分？

向量相似度、全文 rank 和时间分数不同量纲，直接相加不稳定；RRF 只用排名，再让统一的 reranker
学习 query-passage 相关性。

### 10. 为什么不换独立向量数据库？

当前约八千分块，pgvector 足够；同一次检索还要 join 内容状态、来源、时间、实体和 Story。
规模或并发跨过单库边界时再迁移。

### 11. 怎么防止模型编造引用？

模型只输出证据编号，服务器从数据库绑定真实 chunk 和 URL；越界编号剥离，四条不变量失败就拒答，
并对最终 claim-passage 做支持度审计。

### 12. `/eval` 为什么不是实时刷新？

它是发布前的可复现实验：固定黄金集、语料 cutoff 和模型。实时请求在 `/ops`；如果评测随业务数据
漂移，就无法判断指标变化来自代码、模型还是语料。

### 13. 你做过哪些失败实验？

B2 并集比纯稠密差；B8 扫权重接上重排后几乎无差异；B13 中文分词对 RAG 端到端零提升，
但对站内搜索提升 10–32 倍。说明保留负结果能防止“做了就上线”。

### 14. 遇到最有价值的生成 bug？

模型答案正确但偶发不按 JSON，解析失败分支把整段答案清空，误拒升到 7.69%。抓原始响应后修为
带守卫回退，仍复用相同绑定与校验，误拒回到 0%。

## 前端

### 15. 为什么用 SSR？

内容与报告需要首屏 HTML、分享 URL 和搜索引擎可读；同时由 Next 服务端隐藏内部 API 与凭据。

### 16. 页面卡顿怎么查？

先拆导航请求、SSR 数据依赖、外部 API 和浏览器渲染；本项目避免点击时串行拉工程面板，使用
静态评测快照、Core API 缓存和独立路由。不能只用“加 loading”掩盖慢请求。

### 17. 为什么 `/eval` 不自动轮询？

静态评测没有轮询价值；信源后台是运维快照，手动刷新足够。实时健康放 `/ops`，避免每个访客
不断读取管理聚合查询。

## 安全、部署与运维

### 18. 生产如何发布和回滚？

PR/CI 合入 main 后构建带 commit SHA 的镜像；服务器拉取同一 SHA，先迁移再启动，执行公网 smoke；
失败时恢复上一个 SHA，数据库只做向前兼容迁移或从验证备份恢复。

### 19. 2C4G 的瓶颈是什么？

当前模型外置，内存和磁盘比推理 CPU 更敏感。重点监控 PostgreSQL、JVM/Python RSS、镜像与备份空间、
外部 API P95；并发上升或磁盘 70% 以上再扩容。

### 20. 如何迁移服务器而不换域名？

在新机恢复同一镜像和数据，临时地址 smoke，完成备案后改 A 记录，旧机保留回退窗口。产品名和域名
与机器无关，但大陆域名服务需要满足备案要求。

## 主动反问自己

- 如果流量扩大 100 倍，先测哪里，而不是先换什么技术？
- 如果 DeepSeek 改模型输出格式，哪一层会最先报警？
- 如果 Redis 全丢，哪些用户可见事实必须仍然正确？
- 如果一手源与媒体冲突，证据选择如何呈现而不是偷偷裁决？
- 如果 citation precision 自动分数与人工审查冲突，谁是发布判据？

能够回答这些边界，比罗列更多框架更能体现系统设计能力。
