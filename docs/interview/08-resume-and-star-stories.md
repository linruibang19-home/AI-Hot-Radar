# 08｜简历表达与 STAR 故事
## 项目标题

**AI Hot Radar｜可追溯 AI 行业情报与时效 RAG 平台**

Next.js · Spring Boot · FastAPI · PostgreSQL/pgvector · Redis · Docker Compose

## 简历项目描述

独立设计并上线面向 AI 行业的时效情报平台，统一采集 140 个公开来源，完成全文回源、内容结构化、
跨源事件聚类、精选与日/周/月报告，并构建带服务端原文引用、固定发布门和检索解释的混合 RAG；
以不可变镜像部署在 2C4G 单机，完成 HTTPS、邮件订阅、RBAC/审计、告警和备份恢复闭环。

## 建议四条 bullet

- 设计 140 信源增量采集与内容加工管线，覆盖 Feed/API/HTML/GitHub/arXiv 发现、canonical 全文回源、
  SSRF/限速、幂等版本、LLM schema 校验、Story 聚类及日/周/月报告，PostgreSQL 为唯一事实源。
- 构建 pgvector HNSW + PostgreSQL FTS/CJK + 时间/实体约束的混合检索，经 RRF、bge cross-encoder
  重排、事件折叠、父块扩展和服务端引用绑定，在固定 90 题发布集达 Recall@20 89.9%、引用覆盖 98.8%、
  段落支持度 93.4%，可答题误拒 0/78、诱导题错误断言 0/12。
- 将 RAG 轨迹、固定发布评测与动态运行指标产品化，保留 B2/B8/B13 负实验；通过抓取原始模型响应
  定位解析失败导致的 7.69% 误拒，增加带守卫回退且不放松引用不变量，误拒降至 0%。
- 完成 GitHub Actions → GHCR 不可变 SHA 镜像 → 2C4G Docker Compose/Caddy 生产链，建立双确认邮件、
  管理 RBAC/审计、故障/恢复告警、校验和异机备份与隔离恢复。

数字必须加“固定 90 题发布集 / 2026-08-12 快照”等口径；动态内容量答辩前重查。

## STAR 1：解析器造成生成误拒

- **S**：生成侧可答题误拒从 1.28% 上升到 7.69%。
- **T**：判断是检索退化、模型能力变化、语料竞争，还是解析/校验出口问题。
- **A**：先把“语料增长导致位竞争”写成待验证假设；下一轮保存六道失败题原始模型响应，发现答案和
  引用完整，只是偶发直接 Markdown 或把编号只放 `claims[].evidence_ids`；解析失败分支清空正文。
  加入有守卫回退，但仍复用编号绑定、支持度与四条不变量，逐题和全量回归。
- **R**：误拒降为 0/78、诱导题错误断言保持 0/12；更重要的是证伪了听起来合理的初始归因。
- **反思**：可观测性要覆盖模型原始出口和解析阶段，不能只看最终业务指标。

## STAR 2：混合检索不是“加通道就提升”

- **S**：B2 加入 sparse 并集后 Recall/MRR 比纯 dense 更差。
- **T**：确定 sparse 本身无价值，还是融合/排序破坏了候选质量。
- **A**：保留负 run；引入按名次的 RRF 与统一 cross-encoder，记录逐题通道排名；B8 再扫 42 组权重。
- **R**：型号类问题得到真实提升，旗舰证据 dense 14 → sparse 1 → fusion 3；但接上 reranker 后
  权重差距只剩 0.0004，因此决定不改生产权重。
- **反思**：组件价值应看端到端和问题切片，调参没有显著收益就停止。

## STAR 3：跨服务限流接缝

- **S**：匿名 RAG 按 IP 限流看似实现，实际 Next 未正确传递客户端地址，生产请求共用一个桶。
- **T**：找到为什么 Web 与 AI 各自单测通过、端到端行为却错误。
- **A**：沿 Caddy → Next → AI 检查 forwarded header 契约，定义可信代理边界，在接缝添加测试。
- **R**：恢复客户端粒度限流，避免单个用户拖累全站；形成“跨语言边界必须测接缝”的工程规则。
- **反思**：安全 header 不能无条件相信公网输入，修复功能同时要限定信任链。

## STAR 4：信源状态机误隔离

- **S**：一次 DNS 抖动使多个一手源过早进入隔离且无法自然恢复。
- **T**：恢复规格中的失败阶梯，同时保留历史错误和人工控制。
- **A**：按连续失败推进 DEGRADED/QUARANTINED，加入 probe 恢复与审计，不再单次失败永久封禁。
- **R**：一手源恢复且后台能解释最近成功、失败次数与状态变化；全局流水线未因单源停止。
- **反思**：错误状态不是异常字符串，而是需要恢复路径的业务状态机。

## 简历与面试禁区

- 不说“实时 140 个都正常”；登记数与 ACTIVE 数不同且动态变化。
- 不说“实现了消息队列”；outbox 当前没有消费者。
- 不说“引用正确率 100%”；自动段落支持度是 93.4%，还需人工高风险审查。
- 不说“微服务/K8s 架构”；当前是模块化单体 + AI Worker + 单机 Compose。
- 不暴露线上邮箱、API key、服务器 IP/口令、管理 token 与私有配置。
