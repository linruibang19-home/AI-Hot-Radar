# 05｜前端产品与交互
## 前端定位

Next.js 不是数据库的另一个客户端，而是内容产品与内部服务之间的展示边界。内容首屏、详情、
Story、主题和报告优先 Server Component/SSR；筛选、订阅弹窗、多轮问答、引用面板和管理交互
使用 Client Component。浏览器只访问同源 Web，内部 Core/AI 端口与凭据不暴露。

## 页面地图

| 页面 | 主要任务 | 数据口径 |
|---|---|---|
| `/` | 精选、热点和日期时间线 | 当前数据库 + 短缓存 |
| `/items` / `/hot` | 全部动态、分类搜索、热榜 | 已发布内容/Story |
| `/stories` / `/topics` | 跨源事件与主题关系 | Story、entity、topic |
| `/reports` | 日/周/月历史和阅读 | 已保存 PUBLISHED 报告 |
| `/ask` / `/ask/{id}` | 提问、多轮、答案和证据解释 | RAG 实时执行/持久化记录 |
| `/eval` | RAG 发布门、逐轮实验 | 固定评测快照，不自动漂移 |
| `/ops` | 延迟、token、模型、估算成本 | 动态运行聚合 |
| `/admin/models` | 生成模型版本与白名单切换 | 读公开，写受 OPERATOR 保护 |
| `/admin/sources` | 信源运行快照与刷新语义 | Scheduler 写入的当前数据库 |

## 为什么 SSR

内容与报告需要首屏 HTML、稳定分享 URL、canonical/OG/JSON-LD 和搜索引擎可读；同时 Next 服务端
可以隐藏内部地址与 VIEWER 令牌。参数化筛选页用 URL search params 保持可分享、前进后退和服务端
渲染一致，避免再引入一个全局状态真相。

## 内容 UI 的信息层级

- 左侧导航保持内容与工程分组，普通读者先看到精选、动态、热点、事件、报告、主题和问答；
- 卡片先给标题、来源级别、事件/批次时间、摘要，再显示可解释的精选理由；
- 热度不只用颜色，来源标签区分一手、权威二手与社区；
- 日期精度来源只显示日期/批次，不能把抓取时间伪装成 12:00 的发布时间；
- Story 折叠重复报道，但用户仍能查看独立来源和纠正关系。

## 报告 UI

日报、周报、月报使用同一视觉语言和历史导航；页面内容是已保存发布快照，不在请求时调用 LLM。
订阅弹窗在提交前明确：发送日报/周报/月报、收件人时区 08:30、先确认后发送、可随时退订；
提交后区分“确认邮件已发”“已订阅”和失败重试，不让用户误以为输入邮箱就立即群发。

## RAG UI

1. 空态提供问题样例与能力边界；
2. 提交后立即显示用户问题和计划中的时间范围/证据数，避免长模型请求期间像“按钮没反应”；
3. 答案事实句内显示可点击引用编号；
4. 来源面板展示原文标题、日期、来源级别、passage 和 canonical 链接；
5. “为什么是这些证据”解释 dense/sparse、重排、调整和淘汰；
6. 证据不足、部分回答、解析回退和拒答有不同视觉状态；
7. 历史问答有稳定 URL，重新提问会基于最新语料生成新记录。

前端不相信模型 HTML、URL 或引用关系；Markdown 禁任意 HTML，所有引用元数据来自服务端绑定。

## 工程页面的数据语义

- `/eval` 顶部明确语料 cutoff、样本、Embedding、Reranker 和 generation model；仅主动重跑后变化；
- `/ops` 才展示真实请求的近期 P50/P95、token、模型与估算成本；
- `/admin/sources` 展示“本次读取”和最近成功，用户手动刷新取得新快照；页面本身不秒级轮询；
- 价目缺失显示 legacy fallback，不能把估算包装成供应商真实账单。

## 性能与“点击卡顿”排查方法

先按请求链分层测量，而不是先加 loading：

```text
浏览器导航 → Next route/data → Core/AI API → PostgreSQL/Redis → 外部模型
```

内容路由使用 Link 预取、路由级 loading 和服务端缓存；工程重聚合不应跟普通导航串行；RAG 首次请求
主要受外部 embedding/rerank/generation 影响，重复请求由 freshness-aware 缓存加速。实际优化曾把
导航即时反馈与定向预取发布为独立版本，而不是用动画掩盖等待。

## 可访问性、SEO 与响应式

- 语义 heading、键盘焦点、错误说明和不只依赖颜色的状态；
- 尊重 `prefers-reduced-motion`，移动端侧栏转单栏，证据面板转底部；
- item/story/topic/report 有 canonical、OpenGraph 与 JSON-LD；筛选页 `noindex,follow`；
- 删除内容 410、临时不可用 503，不用 404 掩盖状态；
- 图片定尺寸与懒加载，管理/Markdown 重组件不进入首页首包。

## 尚未补齐的产品能力

管理写 API 已具 RBAC、二次确认、幂等和审计，但浏览器写 UI 未实现；若直接把 OPERATOR token 放
localStorage 会扩大 XSS 风险，因此必须先确定短会话/BFF/重新认证方案。真实用户反馈、账号、收藏
同步、租户与 ACL 也不应在只有公开语料时提前引入。
